## 1. 变更动机与目标

### 1.1 背景与问题

平台现有界面为通用浅色风格（浅底、深字、蓝色系强调色），各模块自行设定局部配色，缺少统一的视觉主题约束：仅 M01 的 BR-M01-13 约定了页面头部的**结构**（面包屑 + 标题 + 说明 + 主操作），但从未约定**视觉表现**（色板、字体、间距、圆角、强调色用法）。后果是：

- 组件卡片、侧边导航、文档渲染页、弹窗在色值与间距上互不统一，跨模块体验割裂；
- 与平台「研发智能体」的科技定位不匹配，演示与交付场景缺乏辨识度；
- 各模块硬编码色值（如工作台卡片置灰、未启用态、表格悬停高亮）散落各处，任何一次视觉调整都需要多点修改，回归成本高。

不变更的代价：视觉风格持续发散，后续每新增一个模块都要重复一轮配色对齐，且无法一次性形成可复用的视觉基线。

### 1.2 目标与成功标准

- 目标：将平台界面样式统一改为**黑金系**（深墨黑为底、金为强调），以**设计令牌（Design Token）**方式集中定义并全局下发，业务模块不再硬编码色值；在任意尺寸与任意功能页面上均保持可读性与一致性。
- 成功标准：
  - 平台全部功能页面（环境管理四组页面、组件信息各功能页、实施说明页、全部弹窗与抽屉）在同一套令牌下渲染，无浅色残留区块；
  - 正文文字与背景对比度满足 WCAG 2.1 AA（≥ 4.5:1，大字号与图形 ≥ 3:1）；
  - 修改任一令牌值可全局生效，模块侧无需改动代码（以「改令牌 → 全站变色」可判定达成）；
  - 功能页面的一级信息（标题、主操作按钮、当前导航项）在 3 秒内可被识别（视觉层级可判定）。

### 1.3 非目标（明确不做）

- 不改变信息架构：一级/二级导航的分组、顺序、菜单名称与路由不变（BR-M01-03、BR-M01-04 保持原样）。
- 不改变任何业务规则、数据口径与计算逻辑：组件卡片指标、角标口径、排序规则均不变。
- 不提供**用户级**主题切换：不新增「深色/浅色」偏好设置，黑金为平台唯一视觉主题。
- 不做暗/亮双主题并行维护，不承诺第三方嵌入内容（外部系统 iframe、用户上传的图片文档）的配色适配。
- 不调整页面结构与元素位置；仅为满足对比度与可读性做最小必要微调（如文字色、分隔线）。

### 1.4 关键约束与兼容要求

- **令牌化**：全部颜色、字体、间距、圆角、阴影、动效须以设计令牌定义，业务模块只允许引用令牌，禁止硬编码色值（含内联样式与局部样式覆盖）。
- **可达性与可读性**：正文/次要文字/占位文字与背景的对比度须满足 WCAG 2.1 AA；金色为强调色，**不得**用于长文正文；状态语义（成功/警告/错误/信息）不得仅靠颜色区分，须保留图标或文案。
- **动效与无障碍**：辉光、渐变、过渡动效须响应系统 `prefers-reduced-motion`，在减弱动效时退化为无动画。
- **打印与导出兼容**：导出/打印场景仍须可读——打印样式表回退为浅底深字，不输出大面积深色背景。
- **历史数据**：本次不涉及数据模型变更与数据迁移（纯呈现层）。
- **灰度与回退**：保留原浅色令牌包与**运维级**回退开关（非用户可见），可在一个版本周期内不做代码回滚即恢复浅色基线；观察期至 **2026-10-02**。
- **对外接口稳定性**：不改变任何交易接口、路由契约与埋点事件名。
- **合规**：不得改变状态色的语义可辨识性，以满足审计与运维对告警色的既有认知。

## 3. 变更场景

- 场景描述：使用者登录平台后，在工作台、环境管理与组件信息之间往返操作。变更后，全部页面以深墨黑为底、金色为强调渲染：顶栏与侧边栏为深色面，当前导航项以金色高亮，主操作按钮为金色渐变，卡片与面板以深色面加细金色描边呈现，关键指标数字使用金色；文档类页面（需求文档、设计资产、知识库、平台功能说明）的 Markdown 正文、表格、代码块均为深色适配。使用者的操作路径与业务结果完全不变，仅视觉呈现改变。
- 触发条件：登录平台、切换项目、进入任一功能页面、打开任一弹窗或抽屉、进入文档阅读页——即任何一次界面渲染。
- 参与角色：全部角色（项目架构师、业务分析人员、评审人员、审计人员）；角色切换仅改变展示，不改变视觉主题（BR-M01-10 不变）。
- 主流程：进入平台 → 顶栏与一级导航以黑金主题渲染 → 进入工作台查看组件卡片（深色卡片 + 金色指标）→ 点击卡片进入组件信息（侧边栏当前项金色高亮）→ 在工程仓库选择器中切换工程 → 打开任一功能页面（页面头部与主操作按统一视觉规范呈现）→ 打开文档类页面以深色排版阅读。
- 分支流程：① 打开项目切换弹窗与各类弹窗；② 打开实施说明页（阶段表与平台功能说明文档）；③ 遇到未启用/不可用元素（置灰态在黑金底下的呈现）；④ 导出或打印页面（回退浅色打印样式）。细节展开见 §5 能力变更规格与 §6 界面变更规格。

### MODIFIED 修改能力

#### ft-FT-002-01 修改「全局界面约定」

- 目标模块：M01 / 原能力编号：CAP-M01-09
- 变更前：统一全平台的页面头部、文档阅读与导航角标表现，保证跨模块体验一致。约定内容仅覆盖**结构**：页面头部为「面包屑 + 页面标题 + 一句功能说明 + 右侧主操作按钮组」；面包屑在组件上下文为「{组件名称} / {资产分组}」、在环境管理为「环境管理 / {导航分组}」；Markdown 文档类页面统一渲染正文并提供右侧固定提纲、点击定位并高亮当前章节；列表行鼠标悬停高亮；流程详情页头部以面包屑展示位置、不提供整页返回按钮；二级导航菜单可展示数量角标。原能力的关联规则为 BR-M01-13、BR-M01-14、BR-M01-15，未对任何视觉表现（色板、字体、强调色用法、状态呈现）作出约定，导致各模块自行设定配色，体验割裂且视觉调整需多点修改。
- 变更后（完整重述，非差异片段）：
  统一全平台的页面头部、文档阅读、导航角标与**视觉主题**表现，保证跨模块体验一致。本能力包含两部分约定：
  （一）**结构约定**（沿用基线，不变）：① 页面头部依次展示面包屑、页面标题、一句功能说明与右侧主操作按钮组；② 面包屑在组件上下文形如「{组件名称} / {资产分组}」，在环境管理形如「环境管理 / {导航分组}」；③ 以 Markdown 承载的文档类页面统一渲染正文并提供右侧固定提纲，提纲与正文由同一份内容派生，点击提纲定位章节且当前章节高亮；④ 列表类页面鼠标悬停表格行时该行高亮；⑤ 流程详情页头部以面包屑展示所处流程位置，不提供整页返回按钮；⑥ 二级导航菜单项在其存在数量口径时展示数量角标，口径与该菜单对应模块一致。
  （二）**视觉主题约定**（本次新增）：① 全平台统一使用黑金系视觉主题——深墨黑为界面基底，金色为强调色，由 M01 下发的设计令牌（见 §8「视觉主题令牌」）定义色板、字体、间距、圆角、描边、阴影与动效；② 任意模块的任意界面元素，其颜色、字体、间距、圆角、描边、阴影与动效均须由令牌计算得出，模块内不得硬编码色值或以局部样式覆盖令牌；③ 视觉层级固定为：主操作与当前导航项使用强调金，正文使用高对比浅色，次要信息使用降低明度的中性色，禁用态使用进一步降低明度的中性色并保留可识别的禁用语义；④ 语义状态色（成功/警告/错误/信息）的语义与色相不变，仅做深色基底下的明度适配，且不得与强调金混淆；⑤ 文档类页面的正文、表格、引用块、代码块、分隔线与滚动条均按深色排版渲染；⑥ 打印与导出场景回退为浅底深字样式，不输出大面积深色背景；⑦ 弱动效偏好开启时，渐变、辉光与过渡动效退化为无动画的静态呈现。本能力的结构约定与视觉主题约定对所有模块的功能页面同时生效，任一模块新增页面时自动继承，无需各自重复定义。

#### ft-FT-002-02 新增「黑金视觉主题呈现与令牌下发」

- 目标模块：M01
