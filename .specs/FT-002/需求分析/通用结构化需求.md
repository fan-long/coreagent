# ft-FT-002 界面样式优化（黑金系） —— 结构化需求规格

> 本规格依据《通用结构化需求》模板编制，将 ft-FT-002 的 OpenSpec 增量变更（原始需求）、数据模型设计与已有测试案例转换为统一、可追踪、可验证的需求规格。
>
> 需求条款（RC）是统一追踪单元；共享定义（DEF）提供语义；能力（CAP）组织条款；验收检查点（AC）定义验证义务。
>
> 本规格不替代技术设计、实施任务或测试报告，也不因填写完成而证明实现正确。
>
> 条款编号采用统一追踪编号 RC-FT002-01…RC-FT002-34；「来源」列同时标注源文档的原始编号（ft-FT-002-NN / ft-FT-002-Bn / CAP-M01-09 / CAP-M01-10 / UI-M01-01…UI-M01-07），以便与源文档互查。能力编号沿用源文档的目标编号 CAP-M01-09（修改）与 CAP-M01-10（新增），检查点编号 AC-FT002-01…AC-FT002-39，待决事项编号 Q-FT002-01…Q-FT002-12。

> **增量变更说明**：本规格为 Change 规格（候选目标），相对 M01 模块 Spec 基线（CAP-M01-09 原表述、UI-M01-01…UI-M01-07 原表述，基线无 CAP-M01-10 与 BR-M01-16/17/18）的差异见第 8 节。验收后按源文档 §9「Spec 回写清单」回写为 M01 与各模块 Spec 的新基线。

### 1.2 目标与边界

- **业务目标**：将平台界面样式统一改为**黑金系**（深墨黑为底、金为强调），以**设计令牌（Design Token）**方式集中定义并全局下发，业务模块不再硬编码色值；在任意尺寸与任意功能页面上均保持可读性与一致性。
- **成功标准**（源文档 §1.2，共 4 条）：
  1. 平台全部功能页面（环境管理四组页面、组件信息各功能页、实施说明页、全部弹窗与抽屉）在同一套令牌下渲染，无浅色残留区块；
  2. 正文文字与背景对比度满足 WCAG 2.1 AA（≥ 4.5:1，大字号与图形 ≥ 3:1）；
  3. 修改任一令牌值可全局生效，模块侧无需改动代码（以「改令牌 → 全站变色」可判定达成）；
  4. 功能页面的一级信息（标题、主操作按钮、当前导航项）在 3 秒内可被识别（视觉层级可判定）。
  - 第 4 条无测量口径（无计时起点、无观察方式），登记 Q-FT002-06，见 3.2。
- **建设对象**：core-agent 平台的全局视觉层——M01 下发的设计令牌定义与令牌渲染机制，以及 M01 的 7 个界面单元（顶栏、工作台、环境管理侧边栏、组件信息侧边栏、实施说明页、项目切换弹窗、页面头部与文档阅读约定）的视觉表现；M02–M26 全部含界面的模块的页面渲染层（不改变其业务逻辑）。
- **纳入范围**：
  - 黑金系视觉主题的定义、集中下发与全局渲染（CAP-M01-10 新增）；
  - 全局界面约定在结构与文档阅读之外增加视觉主题承载（CAP-M01-09 修改）；
  - 设计令牌对象（色板、字体、间距、圆角、描边、阴影、动效七组）的数据结构与取值约束；
  - UI-M01-01…UI-M01-07 七个界面单元的变更后视觉规格；
  - 对比度、语义状态色、减弱动效、打印与导出、遗留硬编码兜底等兼容与降级要求；
  - 运维级浅色主题回退开关与观察期（至 2026-10-02）；
  - M02–M26 各模块 Spec §6 界面规格的视觉遵循加注。
- **排除范围**（源文档 §1.3 非目标与 §1.4 关键约束）：
  - 不改变信息架构：一级/二级导航的分组、顺序、菜单名称与路由不变（BR-M01-03、BR-M01-04 保持原样）；
  - 不改变任何业务规则、数据口径与计算逻辑：组件卡片指标、角标口径、排序规则均不变；
  - 不提供**用户级**主题切换，不新增「深色/浅色」偏好设置；不做暗/亮双主题并行维护；
  - 不承诺第三方嵌入内容（外部系统 iframe、用户上传的图片文档原始内容）的配色适配；
  - 不调整页面结构与元素位置，仅为满足对比度与可读性做最小必要微调；
  - 不涉及数据模型变更与数据迁移（纯呈现层）。
- **外部责任**：
  - 令牌的具体名称与色值由设计交付确定，本规格仅承担建议取值与约束（Q-FT002-01）；
  - 各模块功能页面的业务逻辑、数据口径与页面结构由 M02–M26 各自承担，本次仅约束其视觉表现；
  - M03 应用组件（工作台卡片数据源）、M21 工程仓库与工程配置（侧边栏选择器）在 M01 界面中被直接渲染，需一并回归，但其模块责任边界不变；
  - 遗留硬编码浅色样式的清理责任落在各模块，本规格仅规定兜底渲染与标记要求（RC-FT002-28）。

## 2. 共享业务定义

本节统一解释条款使用的概念、结构与取值依据。系统必须遵守的约束由 RC 承载，可引用本节定义或其中的字段、行项，不重复抄写。

### 2.1 概念、对象与数据结构

## 3. 可验证需求条款

### 3.1 条款定义

需求条款是在明确的适用范围和条件下，对目标系统提出的一项可独立判断是否满足的要求。一条条款可以包含同一决策的多个分支，分支以「分支a / 分支b / 分支c」标注并可分别验证。能够分别违反、分别修改的要求已尽可能拆分。

### 3.2 条款类型

| 类型 | 表达内容 | 重点检查 |
|---|---|---|
| 业务规则 | 许可、禁止、决策、计算及业务不变量 | 条件、结论、计算口径、例外及优先级 |
| 功能行为 | 必须执行的动作、状态变化和业务效果 | 触发、动作、完成条件、成功及失败结果 |
| 数据要求 | 数据结构、含义、关系、记录与保留要求 | 对象范围、数据契约、关联及有效性 |
| 交互契约 | 人机或系统间的信息交换与协作 | 输入、输出、错误、关联标识及交互时序 |
| 质量约束 | 规定条件下的质量指标与保障要求 | 环境、负载、指标、阈值及测量口径 |

每条条款选择一个主类型登记。本规格登记 1 条质量约束类条款（RC-FT002-09 对比度阈值），因其阈值与适用范围均由来源明确给出（DEF-FT002-06）；成功标准第 4 条「3 秒内可被识别」因无计时起点与观察方式，不登记为质量约束条款，登记 Q-FT002-06。

> **结构约定（沿用基线，本次不变）**：源文档 §5 CAP-M01-09 的 6 项结构约定（页面头部四段结构、面包屑在组件上下文/环境管理的形态、Markdown 文档类页面的正文与右侧固定提纲及点击定位高亮、列表类页面表格行悬停高亮、流程详情页头部面包屑且无整页返回按钮、二级导航数量角标及口径一致）与 §6 各界面单元的「交互规则」，均为 M01 基线条款 RC-M01-13、RC-M01-14、RC-M01-15、RC-M01-42、RC-M01-43、RC-M01-44 的现行表述，本次**未发生语义变化**，故不在本规格重复登记（处置见 1.4），其单一口径来源为 SRC-005。本规格仅对其**视觉表现**另行提出要求：悬停高亮的令牌化见 RC-FT002-23，头部与文档阅读的视觉表现见 RC-FT002-21、RC-FT002-22，角标的视觉表现见 RC-FT002-17、RC-FT002-18。

### 6.2 验证形式说明

- **场景验证**：给定具体条件、操作或事件，检查预期结果，适合正常、异常、边界和状态分支。本规格多数检查点采用此形式。
- **性质验证**：在明确输入域、状态域或操作序列中检查应持续成立的关系。本规格未单独采用：源文档未规定可形式化的不变量（如令牌值的守恒关系或幂等性），不为使用性质测试而增加原需求没有规定的不变量。
- **测量验证**：在规定环境、负载和时间窗口中测量指标。本规格用于对比度阈值（AC-FT002-11、AC-FT002-12、AC-FT002-38）与语义状态色区分度（AC-FT002-14）；测量环境与取色口径未在来源中规定，依据 Q-FT002-05 结论固化。
- **静态契约检查**：检查结构、声明、接口或其他可静态判定的约束。本规格用于禁止硬编码色值、令牌定义完整性、令牌使用位置、导航与路由不变、接口与埋点不变、页面结构不变、模块 Spec 加注等。

未为使用性质测试而增加原需求没有规定的不变量、幂等或可逆性要求。
