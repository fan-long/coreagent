# M01 工作台与全局导航 —— 结构化需求规格

> 本规格依据《通用结构化需求》模板编制，将 M01 模块的 OpenSpec 能力基线（原始需求）、数据模型设计与已有测试案例转换为统一、可追踪、可验证的需求规格。
>
> 需求条款（RC）是统一追踪单元；共享定义（DEF）提供语义；能力（CAP）组织条款；验收检查点（AC）定义验证义务。
>
> 本规格不替代技术设计、实施任务或测试报告，也不因填写完成而证明实现正确。
>
> 条款编号采用统一追踪编号 RC-M01-01…RC-M01-65；「来源」列同时标注源文档的原始编号（BR-M01-xx / CAP-M01-0x / UI-M01-0x），以便与源文档互查。本次已合并功能点 FT-002（界面样式优化：黑金系）的增量变更，涉及条款在「来源」列标注「FT-002」（见第 8 节）。能力编号沿用源文档 CAP-M01-01…CAP-M01-10，检查点编号 AC-M01-01…AC-M01-75，待决事项编号 Q-M01-01…Q-M01-27。

### 1.2 目标与边界

- **业务目标**：让使用者在任意时刻都能明确「当前处于哪个项目、哪个组件、哪个工程、哪个页面」，并快速到达目标功能。
- **成功标准**：从工作台或环境管理出发，三步内可到达任一模块页面；不可用入口均能说明原因与前置配置位置。（「三步内」无测量口径，见 Q-M01-17）
- **建设对象**：core-agent 平台 M01 模块范围内的顶栏、工作台、环境管理二级导航、组件信息二级导航、实施说明页与项目切换弹窗，以及全局界面约定。
- **纳入范围**：
  - 平台统一入口与两层导航结构（一级导航、二级导航）；
  - 工作台组件概览的展示与从工作台进入组件信息的导航上下文切换；
  - 当前项目切换、角色展示、平台说明与实施说明；
  - 全平台页面头部、文档阅读与导航角标的统一表现约定；
  - 全平台界面（顶栏、工作台、两套二级导航、实施说明页与项目切换弹窗）的黑金系视觉主题呈现与设计令牌下发（来源：FT-002）。
- **排除范围**：
  - 不实现功能权限与操作审计（平台尚未具备该能力，见 SRC-001 §1.3）；
  - 不承载各功能页面内部逻辑（由 M02–M26 对应模块承载）；
  - 不提供全局检索（平台尚未具备该能力）；
  - 第三方嵌入内容（外部 iframe、用户上传的图片与文档原始内容）不在视觉适配范围内（来源：FT-002）；
  - M02–M26 各模块 Spec 对视觉主题的引用回写由对应模块承载，不在本规格范围（来源：FT-002）；
  - 其他跨模块的增量变更（全局检索、功能权限与操作审计等）仍以功能点（ft）方式另行登记，本次 FT-002 已合并部分除外。
- **外部责任**：
  - 各功能页面的内容与业务逻辑由对应模块承担（M02–M26）；
  - 组件主数据、需求规格、主任务类型、工程仓库与框架能力分别由 M03 应用组件、M06 Spec模板与任务类型、M21 工程仓库与工程配置维护；
  - 模型与命令行 Agent 的执行能力由外部工具提供（平台不内置），经通用 Agent 集成配置接入；
  - 组件卡片三项指标的明细口径由 M26 问题跟踪、M23 任务管理、M25 规则库全景承担。

## 3. 可验证需求条款

### 3.1 条款定义

需求条款是在明确的适用范围和条件下，对目标系统提出的一项可独立判断是否满足的要求。一条条款可以包含同一决策的多个分支，分支以「分支a / 分支b / 分支c」标注并可分别验证。能够分别违反、分别修改的要求已尽可能拆分。

### 3.2 条款类型

| 类型 | 表达内容 | 重点检查 |
|---|---|---|
| 业务规则 | 许可、禁止、决策、计算及业务不变量 | 条件、结论、计算口径、例外及优先级 |
| 功能行为 | 必须执行的动作、状态变化和业务效果 | 触发、动作、完成条件、成功及失败结果 |
| 数据要求 | 数据结构、含义、关系、记录与保留要求 | 对象范围、数据契约、关联及有效性 |
| 交互契约 | 人机或系统间的信息交换与协作 | 输入、输出、错误、关联标识及交互时序 |
| 质量约束 | 规定条件下的质量指标与保障要求 | 环境、负载、指标、阈值及测量口径 |

每条条款选择一个主类型登记。基线的质量类表述「三步内可到达任一模块页面」无测量口径，已登记 Q-M01-17，未编造阈值；本次合并的 RC-M01-55 为质量约束类条款，其阈值（4.5:1 / 3:1）与依据（WCAG 2.1 AA）由来源给出，测量口径见 Q-M01-22。

### 6.2 验证形式说明

- **场景验证**：给定具体条件、操作或事件，检查预期结果，适合正常、异常、边界和状态分支。本规格多数检查点采用此形式。
- **性质验证**：在明确输入域、状态域或操作序列中检查应持续成立的关系。本规格用于 RC-M01-03 的导航结构不变性（AC-M01-05）。
- **测量验证**：在规定环境、负载和时间窗口中测量指标。本规格用于对比度阈值（AC-M01-65）与语义状态色区分度（AC-M01-68）；测量环境与取色口径未在来源中规定，依据 Q-M01-22 结论固化。基线质量目标「三步内可到达任一模块页面」仍无测量口径（Q-M01-17），未采用。
- **静态契约检查**：检查结构、声明、接口或其他可静态判定的约束。本规格用于页面头部、顶栏、弹窗与流程详情页的结构约定。

未为使用性质测试而增加原需求没有规定的不变量、幂等或可逆性要求。

后续变更处理约定：

- 同一要求的修订保留 RC 标识并更新规格版本；
- 拆分、合并时记录旧条目与新条目的对应关系，不丢失来源和历史；
- 共享定义（DEF）或适用范围变化时，即使条款正文未改动，也须评估引用它们的条款；
- 规格生效、实施完成和验证通过分别由对应流程及证据判定，不由本规格自行认定；
- 跨模块的增量变更（如全局检索、功能权限与操作审计）以功能点（ft）的 Change 方式另行登记，不直接改写本基线。
