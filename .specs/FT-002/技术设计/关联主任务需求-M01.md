# M01 工作台与全局导航 —— 模块需求（OpenSpec 风格 · 能力基线 Spec）

> 用途：以 OpenSpec Spec 结构描述一个模块当前已具备的能力基线，作为技术设计、代码生成与测试验证的输入。
> 文档类型：Spec（现状基线）；跨模块的增量变更由「功能点（ft）」以 Change 方式另行表达，不写入本文档。
> 编写单位：一个模块一份文档；能力（Capability）是需求的最小可验收单元。
> 通用性说明：本模板为通用模板，不预设任何项目的功能域、分组枚举与模块划分；模块编号、模块名称、所属分组、应用组件标识均取自使用方的模块字典。

## 1. 背景与目标

### 1.1 现状与问题

平台已实现统一入口与全局导航：工作台以组件卡片呈现当前项目概览，环境管理与组件信息分别以二级导航组织功能页面，顶栏提供当前项目切换、角色切换与平台说明入口。现状问题：角色切换仅改变展示，不约束功能权限；部分导航入口依赖组件配置或工程能力，不可用时仅置灰提示。

### 1.2 目标与成功标准

- 目标：让使用者在任意时刻都能明确「当前处于哪个项目、哪个组件、哪个工程、哪个页面」，并快速到达目标功能。
- 成功标准：从工作台或环境管理出发，三步内可到达任一模块页面；不可用入口均能说明原因与前置配置位置。

### 1.3 非目标（明确不做）

- 不实现功能权限与操作审计：平台尚未具备该能力。
- 不承载各功能页面内部逻辑：见对应模块。
- 不提供全局检索：平台尚未具备该能力。

### 1.4 关键约束

- 导航结构为两层：一级导航（工作台、环境管理）与二级导航（环境管理分组、组件信息分组）。
- 组件信息视图必须先选定组件，页面内容随所选组件与工程仓库变化。
- 菜单名称与可用性依赖组件配置（需求规格、主任务类型）与工程框架能力。

## 3. 业务场景

- 场景描述：使用者进入平台后，先从工作台了解当前项目有哪些组件及其健康状态，再进入某个组件查看任务、问题与资产；或直接进入环境管理维护项目与平台配置。
- 触发条件：登录平台、切换项目、从工作台进入组件、在环境管理与组件信息之间往返。
- 参与角色：全部角色。
- 主流程：进入平台 → 工作台查看组件卡片 → 点击组件卡片进入组件信息 → 在组件信息内切换工程仓库并选择功能菜单。
- 分支流程：切换当前项目；进入环境管理维护配置；打开平台说明；在组件信息内切换组件（返回工作台或切换项目）。

## 5. 能力规格（Capabilities & Expectations）

### CAP-M01-01 工作台组件概览

- 目的：集中呈现当前项目下的组件全貌与健康指标。
- 范围边界：只读派生视图；数据来源为 M03 与工程仓库、问题、规则库口径。
- 关联规则：BR-M01-01、BR-M01-02
- 验收预期：
  - GIVEN 当前项目存在若干组件 WHEN 进入工作台 THEN 以卡片网格展示全部组件
  - GIVEN 查看某卡片 WHEN 展示 THEN 含组件图标、名称、状态、功能范围与三项指标（阻塞事项数、任务数量、规则数量）
  - GIVEN 某组件未设置主任务类型 WHEN 查看任务数量指标 THEN 不展示具体口径名称，仅展示占位
  - GIVEN 某组件存在默认工程 WHEN 查看卡片底部 THEN 展示需求规格、工程数量与默认工程版本
  - GIVEN 存在未启用组件 WHEN 查看卡片 THEN 该卡片置灰且排在启用组件之后

### CAP-M01-02 从工作台进入组件信息

- 目的：由组件概览直达该组件的功能区域。
- 范围边界：改变导航上下文，不修改数据。
- 关联规则：BR-M01-02
- 验收预期：
  - GIVEN 点击启用状态组件卡片 WHEN 进入成功 THEN 侧边栏切换为该组件的组件信息导航，并默认选中该组件的默认工程仓库
  - GIVEN 点击未启用组件卡片 WHEN 进入 THEN 仍进入该组件的组件信息
  - GIVEN 工作台点击「管理组件」 WHEN 跳转 THEN 进入应用组件页

### CAP-M01-03 一级导航切换

- 目的：在工作台与环境管理之间切换。
- 范围边界：只切换视图，不改变数据。
- 关联规则：BR-M01-11
- 验收预期：
  - GIVEN 当前在工作台 WHEN 切换到环境管理 THEN 展示环境管理二级导航并进入项目信息页
  - GIVEN 当前在环境管理 WHEN 切换到工作台 THEN 隐藏二级导航并展示工作台

### CAP-M01-04 环境管理二级导航

- 目的：按功能分组组织平台配置类页面。
- 范围边界：导航与路由；页面内容由各模块实现。
- 关联规则：BR-M01-03
- 验收预期：
  - GIVEN 进入环境管理 WHEN 查看侧边栏 THEN 依次展示项目配置（项目信息、应用组件、技术框架）、知识库管理（系统特性）、模板管理（应用类型、Spec模板）、系统配置（模型配置、通用Agent集成、Skill配置、Agent配置、工作流配置）
  - GIVEN 点击某二级导航项 WHEN 切换成功 THEN 主区域展示对应页面且该项高亮
  - 异常预期：GIVEN 页面依赖的数据加载失败 WHEN 打开页面 THEN 保留页面结构并提示失败，不白屏

### CAP-M01-05 组件信息二级导航与工程仓库切换

- 目的：在选定组件与工程仓库的上下文中组织功能入口。
- 范围边界：导航、上下文切换与入口可用性判定；不实现各功能页面。
- 关联规则：BR-M01-04、BR-M01-05、BR-M01-06、BR-M01-07、BR-M01-08、BR-M01-09、BR-M01-12
- 验收预期：
  - GIVEN 已进入某组件 WHEN 查看侧边栏 THEN 顶部展示组件图标、名称、工程仓库数量与工程仓库管理入口，其下提供工程仓库选择器（选项为「工程名称-版本号(默认)」）
  - GIVEN 组件存在多个工程仓库 WHEN 切换选择器 THEN 工程维度页面内容按新工程重新加载
  - GIVEN 查看功能菜单 WHEN 展示 THEN 工程维度含任务管理、服务编排全景、规则库全景、问题跟踪、代码库；组件公共资产按需求文档、设计资产（接口设计、组件数据模型）、测试资产（测试案例）、知识库（组件特性、补充知识、代码参考、反思迭代）四类子分组展示
  - GIVEN 组件已关联需求规格 WHEN 查看需求文档菜单 THEN 菜单名称为该规格名称，未关联时为「传统软件需求」
  - GIVEN 组件已设置主任务类型 WHEN 查看接口设计或测试案例菜单 THEN 菜单名称按该任务类型名称加固定后缀命名；数据模型菜单始终为「组件数据模型」
  - 异常预期：GIVEN 当前工程的应用开发框架不支持编排模式 WHEN 查看服务编排全景入口 THEN 入口置灰并提示框架不支持

### CAP-M01-06 当前项目切换

- 目的：在同一平台内切换项目上下文。
- 范围边界：切换全局数据范围；不修改项目数据本身。
- 关联规则：无（本能力为导航或展示类行为，不直接承载业务规则）
- 验收预期：
  - GIVEN 点击顶栏当前项目名称 WHEN 弹窗打开 THEN 列表展示全部项目，当前项目标记「当前」且无切换按钮
  - GIVEN 选择另一项目 WHEN 切换成功 THEN 顶栏项目名称更新，工作台与各页面按新项目加载数据
  - GIVEN 在弹窗中新增项目 WHEN 名称合法且不重复 THEN 项目创建成功并出现在列表
  - GIVEN 在弹窗中编辑项目名称 WHEN 保存 THEN 列表与顶栏同步更新
  - 异常预期：GIVEN 项目名称为空 WHEN 保存 THEN 拒绝保存并提示

### CAP-M01-07 实施说明与平台说明

- 目的：说明平台在软件工程各阶段的实施定位与 AI 职责，并提供平台功能说明文档的查阅。
- 范围边界：只读展示；阶段表的输出内容可跳转到对应功能页面；不修改任何数据。
- 关联规则：BR-M01-14
- 验收预期：
  - GIVEN 点击顶栏「?」 WHEN 进入 THEN 展示实施说明页且隐藏二级导航
  - GIVEN 停留在「平台功能定位」页签 WHEN 查看 THEN 以表格展示九个实施阶段（架构设计、应用设计、软需分析、技术设计、代码开发、测试验证、知识沉淀、交付归档、运维与维护）的工作项、核心问题、参考资产、输出内容与 AI 职责，AI 职责分为自主、主导、辅助、暂不涉及四类
  - GIVEN 查看阶段表的「输出内容」 WHEN 点击某项 THEN 跳转到该输出对应的功能页面
  - GIVEN 切换到「平台功能说明」页签 WHEN 查看 THEN 从平台文档接口读取说明 Markdown，以左侧提纲、右侧正文渲染，点击提纲定位对应章节且当前章节高亮
  - 异常预期：GIVEN 平台功能说明文档缺失 WHEN 打开页签 THEN 提示暂无文档，不报错
  - 异常预期：GIVEN 平台功能说明文档读取失败 WHEN 打开页签 THEN 展示失败原因，不白屏

### CAP-M01-09 全局界面约定

- 目的：统一全平台的页面头部、文档阅读、导航角标与视觉主题表现，保证跨模块体验一致。
- 范围边界：全局表现约定，不改变各模块业务逻辑与数据。
- 关联规则：BR-M01-13、BR-M01-14、BR-M01-15、BR-M01-16、BR-M01-17、BR-M01-18
- 来源：ft-FT-002
- 结构约定（基线保留）：① 页面头部依次展示面包屑、页面标题、一句功能说明与右侧主操作按钮组；② 面包屑在组件上下文形如「{组件名称} / {资产分组}」，在环境管理形如「环境管理 / {导航分组}」；③ 以 Markdown 承载的文档类页面统一渲染正文并提供右侧固定提纲，提纲与正文由同一份内容派生，点击提纲定位章节且当前章节高亮；④ 列表类页面鼠标悬停表格行时该行高亮；⑤ 流程详情页头部以面包屑展示所处流程位置，不提供整页返回按钮；⑥ 二级导航菜单项在其存在数量口径时展示数量角标，口径与该菜单对应模块一致。
- 视觉主题约定（ft-FT-002 新增）：① 全平台统一使用黑金系视觉主题——深墨黑为界面基底，金色为强调色，由 M01 下发的设计令牌（见 §7「视觉主题令牌」）定义色板、字体、间距、圆角、描边、阴影与动效；② 任意模块的任意界面元素，其颜色、字体、间距、圆角、描边、阴影与动效均须由令牌计算得出，模块内不得硬编码色值或以局部样式覆盖令牌；③ 视觉层级固定为：主操作与当前导航项使用强调金，正文使用高对比浅色，次要信息使用降低明度的中性色，禁用态使用进一步降低明度的中性色并保留可识别的禁用语义；④ 语义状态色（成功/警告/错误/信息）的语义与色相不变，仅做深色基底下的明度适配，且不得与强调金混淆；⑤ 文档类页面的正文、表格、引用块、代码块、分隔线与滚动条均按深色排版渲染；⑥ 打印与导出场景回退为浅底深字样式，不输出大面积深色背景；⑦ 弱动效偏好开启时，渐变、辉光与过渡动效退化为无动画的静态呈现。本能力的结构约定与视觉主题约定对所有模块的功能页面同时生效，任一模块新增页面时自动继承，无需各自重复定义。
- 验收预期：
  - GIVEN 打开任一功能页面 WHEN 查看页面头部 THEN 依次展示面包屑、页面标题、一句功能说明与右侧主操作按钮组，且头部背景为主背景令牌、标题文字为正文令牌、主操作按钮为强调金令牌，不得出现模块自定义色值
  - GIVEN 处于组件上下文 WHEN 查看面包屑 THEN 形如「{组件名称} / {资产分组}」；处于环境管理 WHEN 查看面包屑 THEN 形如「环境管理 / {导航分组}」，分隔符为强调金、当前层文字为强调金
  - GIVEN 打开以 Markdown 承载的文档类页面 WHEN 查看 THEN 正文以深色排版渲染并展示右侧固定提纲，点击提纲定位章节且当前项高亮；表格表头文字为强调金、代码块为深色面
  - GIVEN 浏览列表类页面 WHEN 鼠标悬停表格行 THEN 该行以悬停令牌高亮（明度提升而非改变色相）
  - GIVEN 进入流程详情页 WHEN 查看头部 THEN 以面包屑展示所处流程位置，不提供整页返回按钮
  - GIVEN 查看二级导航 WHEN 该菜单存在数量口径 THEN 展示数量角标，且角标为强调金底 + 深色文字
  - GIVEN 修改任一令牌值 WHEN 刷新页面 THEN 全部引用该令牌的界面元素同步变化，模块侧无需改动代码
  - 异常预期：GIVEN 某模块遗留硬编码的浅色样式 WHEN 打开该页面 THEN 以深色基底与回退文字令牌渲染，不得出现浅底黑字与深底黑字混排导致不可读，且该元素在自检清单中标记为待适配
  - 异常预期：GIVEN 使用者系统开启减弱动效偏好 WHEN 打开含渐变或过渡的页面 THEN 动效退化为静态呈现，信息与操作不受影响
  - 异常预期：GIVEN 使用者执行打印或导出 WHEN 生成结果 THEN 使用浅底深字样式，正文可读且不出现大面积深色背景

### CAP-M01-10 黑金视觉主题呈现与令牌下发

- 目的：以集中定义、全局下发的方式承载黑金系视觉主题，使全平台界面在不改动业务模块代码的前提下获得统一的底色与强调色，并支持运维级回退。
- 范围边界：输入为设计令牌定义（色板、字体、间距、圆角、描边、阴影、动效七组）；本能力只影响呈现层，不产生业务写操作，不改变任何业务数据、路由与接口；令牌对平台全部含界面的模块生效，不联动 M02–M26 的业务逻辑。第三方嵌入内容（外部 iframe、用户上传的图片与文档原始内容）不在适配范围内。
- 关联规则：BR-M01-16、BR-M01-17、BR-M01-18
- 来源：ft-FT-002
- 验收预期：
  - GIVEN 平台启动 WHEN 加载全局样式 THEN 以黑金主题令牌完成初始化，全部界面元素按令牌计算样式，未定义令牌的元素使用回退令牌而非浏览器默认色
  - GIVEN 打开任一模块的功能页面 WHEN 查看 THEN 页面基底为主背景令牌（深墨黑），强调元素（主操作按钮、当前导航项、关键指标数字）为强调金令牌，正文为高对比文字令牌
  - GIVEN 查看处于置灰或禁用状态的元素（未启用组件卡片、不可用导航入口） WHEN 查看其呈现 THEN 以降低明度的中性令牌呈现且保留可识别的禁用语义，文本仍满足对比度要求
  - GIVEN 查看弹窗、抽屉、下拉与提示 WHEN 查看其呈现 THEN 遮罩、面板、边框与主按钮均取自令牌，与页面主体风格一致
  - GIVEN 数据中心或图表类区块 WHEN 渲染 THEN 图表配色取自令牌中的可视化色板，与黑金基底协调且各数据系列可区分
  - GIVEN 运维人员触发浅色主题回退开关 WHEN 刷新页面 THEN 全站恢复原浅色令牌包渲染，业务功能与数据不受影响
  - 异常预期：GIVEN 某令牌未定义或取值非法 WHEN 渲染该元素 THEN 使用回退令牌渲染并记录告警，不出现透明、不可见或不可读元素，页面结构保持完整
  - 异常预期：GIVEN 令牌加载失败 WHEN 打开页面 THEN 保留页面结构并以回退令牌渲染，提示加载失败，不白屏

## 6. 界面规格

### UI-M01-01 顶栏

- 位置与入口：平台所有非说明页顶部
- 页面标题与说明：左侧平台标识与名称；中部当前项目名称；右侧平台说明按钮与角色下拉
- 主操作：一级导航「工作台」「环境管理」
- 元素清单：平台标识（金色描边或金色渐变）、平台名称（高对比文字令牌）、当前项目名称（可点击，悬停转为强调金）、一级导航按钮（当前项文字强调金 + 底部 2px 金色指示条）、平台说明按钮「?」（金色描边圆形按钮）、角色下拉（深色面 + 金色描边）
- 交互规则：点击当前项目名称打开项目列表弹窗；点击一级导航切换视图
- 状态与反馈：当前一级导航项高亮（金色指示条 + 文字强调金）；顶栏背景为深色面令牌，底部 1px 分隔线为低透明度金色；悬停态仅提升明度，不改变色相

### UI-M01-02 工作台

- 位置与入口：一级导航「工作台」
- 页面标题与说明：面包屑为「当前项目名称 / 工作台」，标题为「应用组件」，说明为「当前项目组件基线及默认工程概览」（文案不变，视觉按 CAP-M01-09 视觉主题约定渲染）
- 主操作：「管理组件」（金色渐变主按钮 + 深色文字）
- 元素清单：组件卡片网格（深色面 + 1px 中性描边 + 圆角令牌）；卡片含图标（图标容器金色描边）、名称（高对比文字）、状态标记（语义状态色适配深色底）、功能范围（次要文字色）、三项指标（数字为强调金、标签为次要文字色）、需求规格、工程数量与默认工程版本（次要文字色）
- 交互规则：点击卡片进入组件信息；未启用卡片置灰但可点击
- 状态与反馈：无组件时卡片区为空（空态文案与结构不变，文字按深色底适配）；卡片悬停时描边转为强调金并轻微上浮；未启用卡片整体降低不透明度并保持文字对比度 ≥ 4.5:1
- 来源：ft-FT-002

### UI-M01-03 环境管理侧边栏

- 交互规则：点击导航项切换页面
- 状态与反馈：当前页面导航项高亮（左侧 3px 金色竖条 + 文字强调金 + 低透明度金色底）；悬停态提升明度；侧边栏背景为次级深色面令牌，与主区形成层级差
- 来源：ft-FT-002

### UI-M01-04 组件信息侧边栏

- 位置与入口：从工作台或其他入口进入某组件
- 元素清单：组件图标与名称（图标金色描边、名称为高对比文字）、工程仓库数量（次要文字色）、工程仓库管理入口（金色描边幽灵按钮）；工程仓库选择器（深色面 + 中性描边，展开态描边转强调金）；工程维度菜单（任务管理、服务编排全景、规则库全景、问题跟踪、代码库）（当前项金色竖条，与 UI-M01-03 一致）；组件公共资产子分组（需求文档、设计资产、测试资产、知识库）及各自菜单（同前）

### UI-M01-07 页面头部与文档阅读约定

- 来源：ft-FT-002

| 视觉主题令牌 | 语义说明 | 该令牌的用途与适用场景 | 是 | 文本，须说明何时使用该令牌 | ft-FT-002 |
| 视觉主题令牌 | 适用范围 | 令牌生效的层级 | 是 | 枚举：全局 / 模块 / 界面单元；全局令牌不得被模块覆盖 | ft-FT-002 |

| 组件卡片（派生视图） | 全部指标与底部信息 | 派生计算不变，呈现改为令牌计算（数字使用强调金、标签使用次要文字色） | 是 | 派生计算，口径不变，不单独存储 | ft-FT-002 |
