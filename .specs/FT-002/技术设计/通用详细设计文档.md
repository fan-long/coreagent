## 2. 总体实现方案

### 2.1 技术结构与边界

本变更为**同步的呈现层变更**，不产生业务写操作。技术结构分三层：

1. **令牌定义层（服务端资源，随版本发布）**：令牌以 JSON 令牌包落地于 `classpath:theme/{theme}.json`，与静态基线样式表 `css/tokens.css` 同值；不落数据库。
2. **令牌服务层（后端只读）**：启动期一次性装载令牌包 → 逐项白名单校验 → 组内回退解析 → 缓存不可变令牌包；运行期由只读接口下发，无锁竞争、无数据库访问。
3. **令牌消费层（前端全局）**：首帧由同步加载的静态基线着色；随后异步拉取令牌包，二次校验后原子注入 `:root{--ca-*}` 到单个 `<style id="ca-theme-runtime">`，覆盖基线取值。

令牌生效链路（图中节点为设计单元编号）：

```
                        [启动配置 platform.theme.active]  ← D-006
                                    │
                                    ▼
   D-001 令牌包资源 ──► D-003 启动期装载/校验/回退/缓存 ──► D-004 GET /api/theme/tokens (no-store)
   (dark-gold|light)            │  (逐项回退 + warnings)              │
                                │  (整包失败 → M01-E007 503)          │
                                ▼                                    ▼
                        [服务端告警日志]                    D-005 前端注入 :root{--ca-*} → 原子替换 <style>
                                                                     │
                                    ┌────────────────────────────────┤
                                    ▼                                ▼
                        [成功] D-007…D-015 全部界面单元按令牌计算样式   [失败] 保留 tokens.css 静态基线 + toast 提示（不白屏）
                                                                     │
                                              D-018 硬编码扫描门禁（交付前静态检查）
```

- **同步/异步边界**：令牌装载为启动期同步（`@PostConstruct`），失败不阻断应用启动；前端装载为异步非阻塞，不参与路由视图生命周期。本变更无异步受理、无批量提交、无调度任务。
- **责任分工**：M01 承担令牌定义、下发、全局表现约定与三类降级；M02–M26 只承担「不硬编码色值、遵循令牌」与视觉回归，不承担令牌机制实现；运维承担回退开关的配置与观察期值守。第三方嵌入内容不属本系统适配责任（范围外）。
- **新增 / 修改 / 复用**：新增的是令牌下发接口（新增路由）、静态基线样式表 `tokens.css` 与打印令牌包 `print.css`、错误码 `M01-E007`、令牌包资源与主题配置项、硬编码扫描门禁；修改的是既有样式表与页面脚本中的颜色取值来源（改为引用令牌）；复用既有页面结构、交互与数据口径（不动）。

| 决策编号 | 待解决问题 | 采用方案 | 依据与取舍 | 影响设计单元 |

### D-002 令牌校验规则构件

#### 4.1 责任与边界

- 设计职责：给出单个令牌「合法/非法 + 原因码」的判定规则，供服务端装载期（D-003）与前端注入前（D-005）共用同一套规则。
- 调用者或使用方：D-003（逐项校验）、D-005（前端镜像校验）。
- 依赖：D-001 的分组枚举与值形态；D-002/C-02 的取值形态是 D-001/C-02 的取值约束来源。
- 技术依据：DD-005（安全边界与白名单校验）、DEF-FT002-09-F2/F3、Q-FT002-07（判定规则未闭环，本设计补充并登记 DQ-003）。
- 不承担的责任：不做回退取值选择、不写告警、不决定整包成败（均由 D-003 处理）；不校验令牌的业务用途（用途约束属 D-007）。

#### 4.2 契约与结构

| 契约项标识 | 名称或操作 | 输入/结构 | 输出/约束 | 错误或边界 |
|---|---|---|---|---|
| D-002/C-01 | 分组解析 | 组键字符串 | 命中七组之一返回枚举，否则不存在 | 未知组 → `TOKEN_GROUP_INVALID`，该令牌丢弃 |
| D-002/C-02 | 取值形态校验（按组） | `(group, name, value)` | `color`：`#RRGGBB` 或 `rgba()`，或角度固定 `{n}deg`、色标固定「合法色值+百分比」的 `linear-gradient()`；`font`：字族/字号(rem)/字重(100–900)/行高(无单位)/数字特性；`space`：px 且为 4 的正整数倍；`radius`：px；`border`：`border-width-*` 为 px，线型简写为「宽度 + solid\|dashed + 合法颜色（`var(--ca-*)` 引用或色值）」；`shadow`：`none` 或「偏移+模糊[+扩散]+色值」多层；`motion`：时长 ms、缓动 `ease*` 或各分量 ∈[0,1] 的 `cubic-bezier()` | 不匹配 → `TOKEN_VALUE_INVALID`（该令牌取组回退取值） |
| D-002/C-03 | 危险字符拒绝 | 任意取值 | 含 `;` `{` `}` `<` `>` 一律非法（先于形态校验判定） | 命中 → `TOKEN_VALUE_INVALID`；这是写 `<style>` 场景的注入边界（DD-005） |
| D-002/C-04 | 语义说明必填 | `description` | 非空白 | 缺失 → `TOKEN_DESCRIPTION_MISSING`（该令牌取组回退取值） |
| D-002/C-05 | 适用范围枚举 | `scope` | 取 `GLOBAL` \| `MODULE` \| `UI_UNIT`（大小写不敏感） | 未命中 → `TOKEN_SCOPE_INVALID`；本期下发令牌全部为 `GLOBAL`，模块级/界面单元级的**是否允许**未定义（Q-FT002-03，DQ-012） |
| D-002/C-06 | 名称规范 | `name` | kebab-case：`^[a-z][a-z0-9]*(-[a-z0-9]+)*$` | 不匹配或空 → `TOKEN_NAME_INVALID`，该令牌丢弃 |
| D-002/C-07 | 组内重名检测 | `(group, name)` 全量 | 组内名称唯一 | 重复 → `TOKEN_NAME_DUPLICATED`，该令牌丢弃（保留首次出现项） |
| D-002/C-08 | 原因码清单 | — | `TOKEN_GROUP_INVALID`、`TOKEN_NAME_INVALID`、`TOKEN_NAME_DUPLICATED`、`TOKEN_VALUE_INVALID`、`TOKEN_DESCRIPTION_MISSING`、`TOKEN_SCOPE_INVALID`、`TOKEN_MISSING`（缺失类，由 D-003 用于必备回退判定） | 原因码是下发告警（`warnings[].reason`）的取值域，前端按同一取值域记录 |

> 校验规则为本设计补充（需求仅要求「取值非法要回退并告警」），登记 DQ-003；契约列中的规则在需求侧确认前不作为业务政策，也不作为验收断言（验收断言以 AC-FT002-04/09 的「以回退令牌渲染并记录告警」为准）。

#### 4.3 处理逻辑

| 处理项标识 | 条件或触发 | 技术处理 | 状态/数据/外部效果 | 后续或结束 |
|---|---|---|---|---|
| D-002/P-01 | 收到一条令牌定义（分组已解析成功） | 按顺序判定：说明非空 → 范围枚举 → 名称规范 → 危险字符 → 按组取值形态 | 返回 `null`（合法）或首个命中的原因码 | 合法 → D-003 采用其取值；非法 → D-003 取组回退取值并告警 |
| D-002/P-02 | 分组解析失败，或名称为空/非法/组内重复 | 不进入取值形态判定 | 返回「丢弃类」原因码 | D-003 丢弃该令牌并告警（不注入不可信变量名） |
| D-002/P-03 | 服务端与前端各执行一次同一规则 | 规则镜像实现 | 服务端结论体现在下发数据；前端结论决定是否写入 `<style>` | 任一侧判定非法即不生效（纵深防御） |
