# M02 项目信息 —— 结构化需求规格

> 本规格依据《通用结构化需求》模板编制，将 M02 模块的 OpenSpec 能力基线（原始需求）、数据模型设计与已有测试案例转换为统一、可追踪、可验证的需求规格。
>
> 需求条款（RC）是统一追踪单元；共享定义（DEF）提供语义；能力（CAP）组织条款；验收检查点（AC）定义验证义务。
>
> 本规格不替代技术设计、实施任务或测试报告，也不因填写完成而证明实现正确。
>
> 条款编号采用统一追踪编号 RC-M02-01…RC-M02-32；「来源」列同时标注源文档的原始编号（BR-M02-xx / CAP-M02-0x / UI-M02-0x），以便与源文档互查。能力编号沿用源文档 CAP-M02-01…CAP-M02-06，检查点编号 AC-M02-01…AC-M02-40，待决事项编号 Q-M02-01…Q-M02-15。
>
> 测试案例说明：本阶段输入为「任务类型 mod 任务项 M02 下无未禁用（启用）测试案例」，即 M02 无既有可用测试案例，故本阶段测试案例清单全部为新增案例（无复用、修改与删除项）。

### 1.2 目标与边界

- **业务目标**：让项目名称、建设目标、覆盖范围与工程阶段可被唯一、清晰地维护，并对下游（工作流阶段、Agent 分类、AI 会话上下文）保持一致的投影。
- **成功标准**：保存后顶栏项目名称即时更新；锁定阶段无法被删除或改名；新增阶段在同名 Agent 分类下可立即选择 Agent；阶段改名后原分类下的 Agent 归属不断链。
- **建设对象**：core-agent 平台 M02 模块范围内的项目信息页（环境管理 / 项目配置 / 项目信息）、工程阶段表格、操作反馈与顶栏当前项目展示，以及项目信息的读取、新增与更新处理。
- **纳入范围**：
  - 项目信息的新增、列表读取、按 ID 读取与更新；
  - 工程阶段的定义、空白裁剪、去重、顺序保持、为空回落与锁定阶段校验；
  - 阶段变更对 Agent 一级分类归属的同名同步与迁移；
  - 项目上下文对顶栏「当前项目」与「AI 应用组件设计」会话上下文的投影。
- **排除范围**：
  - 不维护应用组件与技术框架（见 SRC-001 §1.3，对应 M03 应用组件、M05 技术框架）；
  - 不维护工作流阶段、节点与 Agent 绑定（对应 M11 工作流配置）；阶段变更不改写既有工作流阶段（SRC-001 §5 CAP-M02-05 范围边界）；
  - 不维护 Agent 定义与提示词模板（对应 M10 Agent 配置）；
  - 不定义项目级权限、审计与多租户隔离策略（平台尚未具备该能力）；
  - 跨模块的增量变更以功能点（ft）方式另行登记，不在本规格范围。
- **外部责任**：
  - 顶栏「当前项目」的展示与项目切换入口由 M01 工作台与全局导航承担，M02 只提供项目数据与变更后的投影要求；
  - 「AI 应用组件设计」会话上下文的组装由 M27 AI 辅助对话承担（SRC-001 §8 上游），M02 提供项目名称、目标、范围与阶段数据；
  - Agent 一级分类列表的展示与 Agent 归属维护由 M10 Agent 配置承担，M02 只要求分类与阶段同名同步；
  - 既有工作流阶段的补齐与固定标记修正由前端在打开工作流配置页时完成（SRC-001 §1.1），M02 不直接改写工作流阶段；
  - 组件规划 Agent 对项目定位提示的消费由 M03 应用组件承担。

- **对象（DEF-M02-08 Agent 一级分类）**：具有落表（agent_category）与派生（阶段同名分类）两种存在形式；两者的关系与冲突处理未在来源中规定，见 Q-M02-08。

## 3. 可验证需求条款

### 3.1 条款定义

需求条款是在明确的适用范围和条件下，对目标系统提出的一项可独立判断是否满足的要求。一条条款可以包含同一决策的多个分支，分支以「分支a / 分支b / 分支c」标注并可分别验证。能够分别违反、分别修改的要求已尽可能拆分。

### 3.2 条款类型

| 类型 | 表达内容 | 重点检查 |
|---|---|---|
| 业务规则 | 许可、禁止、决策、计算及业务不变量 | 条件、结论、计算口径、例外及优先级 |
| 功能行为 | 必须执行的动作、状态变化和业务效果 | 触发、动作、完成条件、成功及失败结果 |
| 数据要求 | 数据结构、含义、关系、记录与保留要求 | 对象范围、数据契约、关联及有效性 |
| 交互契约 | 人机或系统间的信息交换与协作 | 输入、输出、错误、关联标识及交互时序 |
| 质量约束 | 规定条件下的质量指标与保障要求 | 环境、负载、指标、阈值及测量口径 |

每条条款选择一个主类型登记。本规格不登记质量约束类条款：来源未给出可测量的质量指标（环境、负载、统计窗口、阈值），§1.2 的四项成功标准均为可判定的功能结果，已分别由 RC-M02-22、RC-M02-07、RC-M02-24、RC-M02-10 承载，不编造阈值。

### 6.2 验证形式说明

- **场景验证**：给定具体条件、操作或事件，检查预期结果，适合正常、异常、边界和状态分支。本规格多数检查点采用此形式。
- **性质验证**：在明确输入域、状态域或操作序列中检查应持续成立的关系。本规格未单独采用：来源未给出可枚举的输入域或操作序列不变量（RC-M02-10 的同步关系已通过 AC-M02-12、AC-M02-39 以具体场景验证而非性质验证，避免引入原需求未规定的不变量）。
- **测量验证**：在规定环境、负载和时间窗口中测量指标。本规格未采用：来源未给出可测量的质量指标（见 3.2）。
- **静态契约检查**：检查结构、声明、接口或其他可静态判定的约束。本规格用于存储格式（AC-M02-05）、分类表记录（AC-M02-13）、对象结构（AC-M02-33、AC-M02-34）与页面结构（AC-M02-35、AC-M02-36）。

未为使用性质测试而增加原需求没有规定的不变量、幂等或可逆性要求。
