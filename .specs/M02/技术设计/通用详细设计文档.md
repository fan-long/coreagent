## 2. 总体实现方案

### 2.1 技术结构与边界

M02 延续平台的**单应用两层结构**（无构建步骤的静态前端 + Spring Boot REST 后端 + 单一关系数据库），不新增中间件、不新增部署单元、不新增构建步骤。M02 的位置是「项目级全局上下文的唯一维护者」：它既是 M01 顶栏与全局导航的数据来源，也是 M10 Agent 分类、M11 工作流阶段与 M27 会话上下文的阶段基准来源。

**技术构件与职责分工**

| 层次 | 构件 | 技术形态 | 在 M02 中的职责 |
|---|---|---|---|
| 表现层 | 项目信息页 | `static/js/pages/ProjectInfo.js`（新增）、`static/js/core/store.js`（扩展）、`static/js/main.js`（路由分派） | 表单渲染、阶段表格交互、本地校验与浮动提示、保存后会话态同步；不承载锁定阶段的服务端判定 |
| 接口层 | 项目接口 | `api/ProjectController`（复用 + 修改） | 协议转换、请求头解析、字段出现性判定、HTTP 状态与错误体映射 |
| 处理层 | 项目处理构件 | `service/ProjectService`（复用 + 修改） | 读取定位、名称与目标范围校验、保存编排、默认项目行创建、事务边界 |
| 处理层 | 阶段规则构件 | `service/ProjectStageService`（新增） | 阶段文本解析、规范化（裁剪/去重/保序/忽略空项/回落）、锁定阶段校验、序列化 |
| 处理层 | 阶段同步构件 | `service/AgentCategorySyncService`（新增） | 阶段改名判定与 Agent 一级分类归属迁移 |
| 数据层 | 数据访问构件 | `repository/ProjectInfoRepository`（扩展）、`repository/AgentDefinitionRepository`（新增） | `project_info` 读写；`agent_definition.category` 的批量迁移写入 |
| 支撑层 | 常量与错误码 | `support/StageCatalog`（新增）、`support/ErrorCode`（扩展） | 锁定阶段与默认阶段序列的集中声明；M02 码位与文案 |
| 复用层 | 全局约定 | `support/GlobalExceptionHandler`、`support/BizException`、`support/ApiHeaders`、`static/js/core/notice.js`、`static/js/core/http.js`、`static/js/layout/AppHeader.js` | 统一异常出口、请求头解析、轻提示与失败块、顶栏投影（均为 M01 既有构件，本设计复用不改语义） |

**数据存储与外部依赖**

- 唯一持久化存储为关系数据库（MySQL，经 `spring-boot-starter-data-jpa` 访问）。M02 不引入缓存、消息队列、调度器或搜索引擎。
- `spring.jpa.hibernate.ddl-auto=none`：表结构不在应用启动时生成，由外部 DDL 管理。因此本设计提出的任何索引或列宽调整都属于**外部 DDL 变更**，不作为应用的自动行为（见第 8 节）。
- 无外部系统调用。M02 的上游数据（项目）在本库内；下游（Agent 分类、工作流阶段、AI 会话）由 M10/M11/M27 读取或承载，M02 只负责**写入阶段来源与 Agent 分类归属**两类数据。

**数据流动**

```
项目信息页(静态前端)
   │  ① GET /api/projects/current（读取当前项目定义，含阶段回落）
   │  ② PUT /api/projects/{id}（保存名称/目标/范围/阶段）
   ▼
ProjectController ──► ProjectService ──► ProjectStageService（解析·规范化·锁定校验）
   │                      │            └► AgentCategorySyncService（改名判定·迁移）
   │                      ▼
   │                 ProjectInfoRepository / AgentDefinitionRepository ──► MySQL
   │                                                    （project_info 读写；agent_definition.category 迁移）
   ▼
ProjectDetailVO / ApiError（JSON）
   │
   └─► 顶栏「当前项目」名称（M01 D-M01-09，经前端会话态）
   └─► Agent 分类列表（M10，按阶段序列动态派生；M02 不写 agent_category）
   └─► 「AI 应用组件设计」会话上下文（M27，读取项目定义后组装）
```

- 请求方向：M02 的全部交互为「读取项目定义」与「保存项目定义」两类；读取有按 ID、按当前上下文、列表三种定位，保存有新增、按 ID 更新、缺省更新三种定位。
- **同步、无异步、无批量、无调度**：需求规格 4A 各能力的「受理/完成条件」均为页面渲染或保存完成，不存在异步受理态、批次提交、后台任务或定时触发。阶段改名迁移虽然是一次批量 UPDATE，但它发生**在用户保存请求的同一事务内**，属同步处理，不构成异步机制。
- 构件是**无状态**的：当前项目由前端持有并经 `X-Project-Id` 请求头传递，后端不隐式持有用户或会话状态；`spring.jpa.open-in-view=false` 要求装配在服务层事务内完成。

**本系统、外部系统与人工活动的责任分工**

| 活动 | 责任方 |
|---|---|
| 项目名称、目标、范围与工程阶段的维护；阶段规范化与锁定校验；阶段改名时的 Agent 分类归属迁移 | 本系统（M02） |
| 顶栏「当前项目」的展示与项目切换入口 | 外部模块（M01，复用既有构件，M02 只提供投影要求） |
| Agent 一级分类列表的展示、派生分类与落表分类的叠加、Agent 归属的日常维护 | 外部模块（M10）；M02 只保证「阶段名 = 分类名」的来源侧一致（RC-M02-10、RC-M02-11） |
| 工作流阶段、节点与 Agent 绑定的重建与补齐 | 外部模块（M11）与前端；M02 明确**不改写**既有工作流阶段（RC-M02-10 的例外） |

**新增、修改或复用**

- M02 范围为**复用 + 新增 + 修改并存**：项目信息的读取与保存端点复用 M01 的 `/api/projects` 家族（DD-M02-01），阶段规范化与锁定校验、改名迁移、注入契约、页面构件为新增，`project_info` 查询排序、`stages` 空值回落、`PUT` 请求体语义为对既有实现的修改。
- 新增仅限：阶段规则构件、阶段同步构件、一个最小映射的 `agent_definition` 数据访问构件、M02 错误码与常量、项目信息页与前端会话态扩展、验证资产（第 7 节，属工程验证而非业务功能）。
- 明确不新增：不新增项目表（`project_info` 已存在且字段满足 RC-M02-27）；不新增 Agent 分类落表记录（RC-M02-11）；不新增会话表或会话接口（M27 范围）；不新增公开接口用于测试便利（见 4.5 约束）。

## 4. 设计单元详细规格

### D-M02-01 项目信息读取接口

#### 4.1 责任与边界

- 设计职责：提供项目列表、按项目 ID 读取项目定义明细、按当前上下文读取项目定义明细三种读取；在读取路径完成工程阶段的解析与空值回落；在平台不存在任何项目时创建默认项目行后返回。
- 调用者或使用方：D-M02-05（项目信息页加载）、D-M02-11（页面路由接入与保存后重载）、D-M02-07（会话注入取数）、M01 的 D-M01-10（项目列表弹窗读取列表）、M01 的 D-M01-01（全局上下文间接读取项目清单）。
- 依赖：D-M02-03（阶段解析与回落）、D-M02-08（默认项目行名称）、D-M02-10（数据访问）、D-M02-09（失败出口）、DD-M02-02（缺省定位）、DD-M02-03（自动创建的触发范围）。
- 技术依据：RC-M02-05、RC-M02-12、RC-M02-20、RC-M02-25、RC-M02-27、RC-M02-28；DEF-M02-07、DEF-M02-11、DEF-M02-12。
- 不承担的责任：不做任何项目定义的更新；不判定阶段锁定（属 D-M02-03，读取路径不校验锁定）；不实现页面的加载/失败渲染（D-M02-05）；不补默认项目到列表接口与全局上下文接口（DD-M02-03）。

#### 4.2 契约与结构

| 契约项标识 | 名称或操作 | 输入/结构 | 输出/约束 | 错误或边界 |
|---|---|---|---|---|
| D-M02-01/C-01 | `GET /api/projects` | 请求头 `X-Project-Id`（可选）；无请求体与查询参数 | `200` + `ProjectVO[]`：每项 `{id:Long, name:String, current:boolean}`，**排序 `ORDER BY id ASC`** | 无业务错误码；无项目时返回 `[]`；**本端点不触发默认项目行创建**（DD-M02-03） |
| D-M02-01/C-02 | `GET /api/projects/{id}` | 路径参数 `id:Long` | `200` + `ProjectDetailVO` | `id` 不存在 → `M01-E003`（404），消息 `项目不存在：{id}`（D-M02-09/C-04） |
| D-M02-01/C-03 | `GET /api/projects/current` | 请求头 `X-Project-Id`（可选） | `200` + `ProjectDetailVO`；定位规则见 C-07 | 平台无任何项目时**创建默认项目行后返回** `200`（RC-M02-20）；路径匹配要求：字面量段 `current` 的优先级必须高于变量段 `{id}` |
| D-M02-01/C-04 | `ProjectDetailVO` 结构 | — | `{id:Long, name:String, goal:String\|null, scope:String\|null, stages:String[], lockedStages:String[], updatedAt:String\|null}`；字段顺序为稳定契约 | `goal` / `scope` 为空时下发 `null`（不补空串）；**不下发** `created_at`（`project_info` 无此列，DEF-M02-11） |
| D-M02-01/C-05 | `stages` 的解析与回落 | `project_info.stages`（`text`，可能是英文逗号分隔文本、JSON 数组或 NULL） | 解析为字符串数组（规则见 D-M02-03/C-01）；解析结果为空集合时返回默认五阶段（DEF-M02-07）；两种情况均返回 `200` 且不报错 | 解析异常不使接口失败（沿用既有容忍策略）；**回落值不回写存储**（DD-M02-04） |
| D-M02-01/C-06 | `lockedStages` 的取值 | — | 恒为 DEF-M02-06 的四项锁定阶段，顺序固定；供 D-M02-05 渲染只读行，避免前端复制锁定阶段清单（DD-M02-05 的同类考虑） | 与 `stages` 无包含关系要求：读取回落值含全部四项锁定阶段；存量数据缺少锁定阶段时按原值返回（读取不做锁定校验） |
| D-M02-01/C-07 | 缺省定位规则（供读取与更新共用） | `X-Project-Id` 解析结果（`Long` 或 `null`） | 命中 `project_info.id` 时取该条；未命中或为 `null` 时取 `id` 最小的一条；无任何项目时为 RC-M02-20 的创建分支 | 复用 M01 `D-M01-04/C-07` 的单点实现，不另写一份定位逻辑（DD-M02-02） |
| D-M02-01/C-08 | 默认项目行的内容 | — | `name` = DEF-M02-12「AI新一代核心系统」；`goal` / `scope` = `null`（见 DQ-M02-05）；`stages` = DEF-M02-07 默认五阶段的英文逗号分隔文本；`updated_at` = 当前时间 | 需求未给出默认目标、范围与阶段的文本内容（Q-M02-05）；本设计**不编造文本**，目标与范围按空值处理，阶段按 DEF-M02-07 处理 |
| D-M02-01/C-09 | 读取失败的表现 | — | 数据访问异常经 D-M02-09 统一出口返回 `M01-E006`（503），**不返回空数组/空对象冒充成功** | 前端据此渲染失败提示而非空白表单（RC-M02-25，前端侧由 D-M02-05 承接） |
| D-M02-01/C-10 | 派生展示信息 | 明细响应的 `stages` 数组 | 阶段序号 = 元素下标 + 1；阶段数量 = 数组长度（去重后的项数）；二者**不落库** | 落实 RC-M02-28；序号徽标的补零格式由 D-M02-05 承担 |

#### 4.3 处理逻辑

| 处理项标识 | 条件或触发 | 技术处理 | 状态/数据/外部效果 | 后续或结束 |
|---|---|---|---|---|
| D-M02-01/P-01 | 收到 `GET /api/projects` | 解析 `X-Project-Id`；查询全部项目并按 `id ASC` 排序；逐项计算 `current`（等于生效项目标识者为 `true`） | 只读 | 返回 `200` |
| D-M02-01/P-02 | 收到 `GET /api/projects/{id}` | 按主键查询；命中则进入 P-04 | 只读 | 未命中 → P-03 |
| D-M02-01/P-03 | 按 ID 未命中 | 抛 `M01-E003`（404），消息携带请求携带的项目 ID | 无写入 | 结束（异常出口） |
| D-M02-01/P-04 | 收到 `GET /api/projects/current` | 按 C-07 解析生效项目 | 只读 | 有项目 → P-05；无项目 → P-06 |
| D-M02-01/P-05 | 已定位项目 | 解析 `stages`（调用 D-M02-03/C-01）；结果为空集合时替换为默认五阶段（D-M02-03/C-05） | 只读 | → P-07 |
| D-M02-01/P-06 | 平台无任何项目 | 在同一事务内创建默认项目行（C-08）并作为生效项目 | **写库**：`project_info` 新增 1 行 | → P-05（新行阶段字段已为默认五阶段文本） |
| D-M02-01/P-07 | 已取得项目与阶段 | 装配 `ProjectDetailVO`：字段映射 + `lockedStages` 常量 + `updatedAt` 格式化 | 只读 | 返回 `200` |
| D-M02-01/P-08 | 任一步骤抛出数据访问异常 | 不捕获，交 D-M02-09 统一处理 | 事务回滚（P-06 已写入的默认行不保留） | 返回 `M01-E006`（503） |

- 读取事务：`GET /api/projects`、`GET /api/projects/{id}` 为只读事务；`GET /api/projects/current` 在无项目时为**写事务**（P-06）。
- 空集合前置判断：列表为空时不得回落到「取第一条」以外的逻辑（无项目即 `[]`），避免把「无项目」误判为「默认项目已存在」。

#### 4.4 状态、数据与失败处理

- 读写数据：读 `project_info`；仅在 P-06 分支写 `project_info`（新增默认项目行）。不读不写任何其他表。
- 事务边界：`current` 的创建与读取在同一事务内完成，提交后可观察结果为「`project_info` 新增 1 行且接口返回其内容」；其余读取为只读事务，无副作用。
- 并发冲突：两个并发请求同时命中 P-06 时都可能创建默认项目行（`project_info` 无唯一业务键，DEF-M02-11），产生多条默认项目。识别与处理机制**不在本设计内确定**——需求未规定并发与幂等策略（Q-M02-07），本设计不引入分布式锁、不加唯一约束（见 DQ-M02-07）。
- 重复请求：`GET /api/projects` 与 `GET /api/projects/{id}` 幂等；`GET /api/projects/current` 在已有项目后幂等，在 P-06 分支首次调用会写入，重复调用不再写入（第二次已有项目）。
- 失败处理：读取失败不产生部分响应；P-06 的写入失败与读取失败一并回滚并返回 `M01-E006`。**不默认增加重试**。
- 状态一致性：同一次响应内的 `stages`、`lockedStages`、`id`、`name` 来自同一行记录，不存在「名称与阶段取自不同版本」的中间态。
- 错误分类与传播：仅经 D-M02-09 出口；本单元不新增错误码。

#### 4.5 质量与可验证性

- 安全：读取接口不接收任何可写输入（除 `X-Project-Id`）；不返回账号、密钥等敏感字段；`goal` / `scope` 为项目自述文本，可安全下发；`current` 的创建分支是唯一的写入口，且其写入内容完全由系统常量决定，不接受外部输入。
- 性能：列表全量返回（项目为低频主数据，需求未要求分页；加装分页会改变「展示全部项目」的可观察结果）；列表查询需 `project_info` 全表扫描（表无索引，主键排序在 InnoDB 上走聚簇主键，量级可控）；明细与当前项目读取为点查。
- 日志与诊断：创建默认项目行记录 `info` 日志（含新行标识）；`stages` 解析失败记录 `warn`（沿用 D-M02-03）；系统异常记录 `traceId`（D-M02-09/C-05）。
- 可验证观察入口：`GET /api/projects` 的**数组顺序**即 RC-M02-12 的判定观察入口（AC-M02-14）；`GET /api/projects/current` 的 `stages` 支撑阶段回落判定（AC-M02-06、AC-M02-40）；默认项目行的创建支撑 AC-M02-23；`lockedStages` 支撑页面只读渲染（AC-M02-09）。
- 受控验证：默认项目行的构造需清空 `project_info`（可受控）；阶段回落的三种数据形态（NULL、空串、仅含分隔符）可逐一构造；名称长度计数口径见 DQ-M02-14。
- 敏感信息：无。

#### 4.6 复用核对

- 资产标识及版本：`api/ProjectController`（`GET /api/projects`）、`service/ProjectService#list` / `#resolveCurrent`、`service/ContextService#parseStages`、`api/dto/ProjectVO`、`repository/ProjectInfoRepository#findAllOrdered` / `#findFirstByOrderByIdAsc`（代码基线）；M01 设计 `D-M01-01/C-04`、`D-M01-04/C-01…C-03`、`D-M01-04/C-07`（`.specs/M01/技术设计/通用详细设计文档.md` v1.0）。
- 已核对内容：列表端点的输入输出与 `current` 标记语义；缺省定位的实现（命中 → 否则取 `id` 最小 → 无则 `null`）；`stages` 的解析容忍策略（JSON 数组与分隔符文本）；读取失败不使上下文接口整体失败的约定。
- 与本次需要的差异：
  1. **列表排序**：现状 `findAllOrdered` 为 `updated_at DESC, id DESC`，RC-M02-12 要求 `id ASC`；M01 设计 `D-M01-04/C-02` 将其表述为「排序为技术选择，需求未规定」。处理方式：按 RC-M02-12 修改查询（DD-M02-12），并登记 DQ-M02-16 说明跨模块影响与 M01 设计表述需同步更正。
  2. **阶段空值回落**：现状 `ContextService#parseStages` 对空文本返回 `[]`，M01 设计 `D-M01-01/C-04` 把该行为固化为契约；RC-M02-05 要求回落默认五阶段。处理方式：阶段解析规则集中到 D-M02-03 并实现回落，读取路径（本单元 P-05）与全局上下文路径（D-M02-12/P-08）**共用同一规则**；M01 的契约表述需同步更正（DQ-M02-18）。
  3. **明细读取与当前项目读取**：现状无 `ProjectDetailVO` 与两个新端点（`GET /api/projects/{id}`、`GET /api/projects/current`），M01 设计未涉及（M01 只读取项目名称与阶段）。处理方式：新增，`ProjectVO` 保持原字段不变。
  4. **默认项目行创建**：现状无任何自动创建逻辑，M01 设计 `D-M01-01/C-02` 明确「不由本接口补默认项目」。处理方式：新增于本单元，且按 DD-M02-03 限定触发范围，不改变 M01 上下文接口与列表接口的既有可观察结果。
- 处理方式：复用（端点风格、`current` 标记语义、缺省定位实现、解析容忍策略）+ 修改（排序、空值回落）+ 新增（两个端点、明细契约、默认项目行创建）。
- 影响范围：`ProjectService#resolveCurrent` 被 M01 的 `D-M01-01`、`D-M01-02`、`D-M01-04` 与本次的 D-M02-01、D-M02-02 共同复用，其口径变更会影响全部页面的取数范围；`findAllOrdered` 的排序变更同时影响 M01 项目列表弹窗的项目次序（不影响其检查点断言，见第 8 节）。

- 不承担的责任：不定义阶段规则本身（D-M02-03）；不判定或执行 Agent 归属迁移（D-M02-04）；不创建组件、工作流与 Agent（RC-M02-18 的边界，本设计不新增任何相关写路径）；不决定名称唯一性范围（DD-M02-14、DQ-M02-17）；不实现前端提示与表单（D-M02-05）。

#### 4.2 契约与结构

| 契约项标识 | 名称或操作 | 输入/结构 | 输出/约束 | 错误或边界 |
|---|---|---|---|---|
| D-M02-02/C-01 | `POST /api/projects` | 请求体 `{"name":String, "goal":String?, "scope":String?, "stages":String[]?}` | 校验通过则创建并返回 `201` + `ProjectDetailVO` | 名称不合法 → `M02-E001` / `M02-E002`（400）；名称重复 → `M01-E002`（409，沿用，DD-M02-14）；**不自动创建组件、工作流与 Agent** |
| D-M02-02/C-02 | `PUT /api/projects/{id}` | 路径参数 `id:Long`；请求体为**部分更新**（C-05） | 校验通过则更新并返回 `200` + `ProjectDetailVO` | `id` 不存在 → `M01-E003`（404），消息 `项目不存在：{id}`（RC-M02-21）；**不得静默回落为更新首个项目** |
| D-M02-02/C-03 | `PUT /api/projects` | 请求体同 C-02，**无路径参数** | 按缺省定位（D-M02-01/C-07）确定更新目标并返回 `200` + `ProjectDetailVO` | 定位失败（平台无任何项目）→ `M01-E003`（404）；该边界的提示文案形态需求未规定，见 DQ-M02-20 |
| D-M02-02/C-04 | 名称规范化与校验 | `name`（可为 `null`，亦可未出现） | 未出现 → 不修改名称；出现 → 裁剪首尾空白；裁剪后为空 → `M02-E001`；裁剪后长度 > 128 → `M02-E002` | 长度计数口径（码点 / 码元、是否按裁剪后计算）需求未规定（Q-M02-14），本设计按「裁剪后 + `String.length()`」实现，见 DQ-M02-14 |

| D-M02-02/C-06 | `goal` / `scope` 的规范化 | 字符串或 `null` | 裁剪首尾空白；裁剪后为空串 → 存 `null`；不触发名称类校验 | 落实 RC-M02-03 分支a/b/c、RC-M02-27；空值含义为「未填写」，不表示禁用（DEF-M02-03、DEF-M02-04） |
| D-M02-02/C-07 | `stages` 的规范化与校验 | 字符串数组或未出现 | 未出现 → 不修改阶段（M01 改名路径不传 stages）；出现 → 按 D-M02-03/C-02 规范化，再按 D-M02-03/C-03 校验锁定阶段，再按 D-M02-03/C-04 序列化为英文逗号分隔文本 | 规范化后不得为空集合：保存路径要求四项锁定阶段齐全，故结果至少 4 项（D-M02-03/C-04）；空数组或全为空白项的数组必然触发 `M02-E003` |
| D-M02-02/C-08 | 新增项目的阶段默认 | `stages` 未出现或为 `null` | 按 DEF-M02-07 默认五阶段存储 | 落实 RC-M02-19；与 RC-M02-05（读取回落）分别适用，不得互相替代 |
| D-M02-02/C-09 | 保存的事务顺序 | — | 同一事务内依次：定位目标 → 名称校验 → 目标范围规范化 → 阶段规范化与锁定校验 → 改名判定与迁移（D-M02-04）→ 写入项目行 → 提交 | 锁定校验**优先于**改名判定（RC-M02-07 优先于 RC-M02-09）；任一步失败即回滚，阶段与 Agent 分类保持变更前状态（RC-M02-17） |
| D-M02-02/C-10 | 保存后的可观察结果 | — | `project_info` 该行的 `name` / `goal` / `scope` / `stages` 与 `updated_at` 变更；阶段改名时 `agent_definition.category` 同步迁移；**`agent_category` 无任何变更** | 落库值为裁剪后文本、空值或英文逗号分隔文本（AC-M02-04、AC-M02-05） |
| D-M02-02/C-11 | 名称唯一性（沿用） | — | 名称与**其他**项目重复时返回 `M01-E002`（409） | 该分支来自 M01 的 RC-M01-30，M02 需求未要求唯一性（RC-M02-27 明确不引入），见 DQ-M02-17 |

- 请求体的解析方式：为区分「键不存在」与「键存在但值为空」，请求体以 `Map<String,Object>`（或等价的键集可观测结构）承接，不使用「未提供字段恒为 `null`」的定长 DTO（DD-M02-07 的取舍）。
- `POST` 与 `PUT` 的响应体一致（均为 `ProjectDetailVO`），便于前端保存后直接以响应刷新会话态，不额外发起读取。

| D-M02-02/P-02 | 名称合法 | 校验名称是否已存在（沿用既有全表范围校验）；已存在 → 抛 `M01-E002` | 只读 | 不存在 → P-03 |

#### 4.4 状态、数据与失败处理

- 读写数据：读 `project_info`（定位与重复校验）；写 `project_info`（新增或更新）；条件写 `agent_definition`（仅改名的迁移分支）。不写 `agent_category`、不写任何会话表。
- 事务边界：新增、更新各为**单个写事务**，阶段更新与 Agent 归属迁移在同一事务内；提交后可观察结果为「列表/明细中出现新项目」「该项目字段已变更且 `updated_at` 已更新」「改名场景下原分类下 Agent 的 `category` 已迁移」。无跨系统一致性要求（无外部调用）。
- 并发冲突：两名用户并发保存同一项目时后提交者覆盖先提交者（无乐观锁，数据模型未采用 `version` 字段，第八章第 1 项）；并发保存下改名判定的比对基准取各自事务内的读取值（读写提交语义），**并发保存的处理口径需求未规定**（Q-M02-04），见 DQ-M02-04。本设计不引入版本号或加锁。
- 重复请求：`PUT` 幂等（同名同值重复提交结果一致，`updated_at` 会刷新，属可观察的合理结果）；`POST` 非幂等，重复提交由唯一性分支拒绝（DD-M02-14）。
- 部分失败：不提供部分成功语义。阶段校验失败不写入任何字段（整次保存拒绝）；迁移失败使整个事务回滚，不允许「阶段已改名而 Agent 未迁移」。**不默认增加重试或补偿**（RC-M02-17 明确补偿方式属实现层决策，本设计选择回滚而非补偿）。
- 资源占用与释放：无长事务；不占用连接之外的资源。
- 错误分类与传播：`M02-E001` / `M02-E002` / `M02-E003`（400）、`M01-E002`（409）、`M01-E003`（404）、`M01-E006`（503），均经 D-M02-09 统一出口；前端按码位在页面内提示（D-M02-05）。
- 状态一致性：保存成功后，`project_info` 与 `agent_definition` 处于同一事务提交后的状态，不存在「阶段已改名、Agent 未迁移」的半完成态。

#### 4.5 质量与可验证性

- 安全：名称长度上限（128）与阶段数量由锁定校验间接约束；接口无批量写入、无文件上传；当前无鉴权机制（需求排除范围），故本设计**不声称**已有访问控制。日志不记录请求体全文（`goal` / `scope` 为项目自述文本，虽非密钥类敏感数据，仍按最小化记录）。
- 性能：单次保存为「1 次定位查询 + 1 次重复校验查询（仅名称出现时）+ 1 次更新 + 0–1 次分类迁移更新」；阶段数量与名称长度上限受 DEF-M02-02 与列宽约束，量级可控。
- 日志与诊断：保存成功记录 `debug`（含项目标识与是否发生迁移）；迁移记录受影响行数（不改变判定结果，仅用于诊断）；系统异常记录 `traceId`。
- 可验证观察入口：`POST` 的 HTTP 状态与后续记录支撑 RC-M02-18、RC-M02-19；`PUT` 后 `project_info` 各字段实测值支撑 RC-M02-03、RC-M02-04；`M02-E001` / `M02-E002` / `M02-E003` / `M01-E003` 的状态码与文案支撑 RC-M02-01、RC-M02-02、RC-M02-07、RC-M02-21；`agent_definition.category` 实测值支撑 RC-M02-09。对应 AC-M02-01…AC-M02-05、AC-M02-08、AC-M02-10、AC-M02-11、AC-M02-15、AC-M02-16、AC-M02-18、AC-M02-19、AC-M02-21、AC-M02-22、AC-M02-24。
- 受控验证：名称空/超长、缺少 1 个或多个锁定阶段、阶段含空白与重复项、1 删 1 增与仅删除三类数据均可完全受控构造；迁移失败以真实写入异常触发（不以桩替代），见 V-M02-20、V-M02-41。
- 敏感信息：无。

  4. 现状无阶段相关逻辑。处理方式：新增并外置到 D-M02-03 / D-M02-04，保存接口只做编排。

- 影响范围：本项目保存端点被 M01 项目列表弹窗与 M02 项目信息页共同调用，任何语义变更都会同时影响两处；`M01-E003` 的消息变更会影响 M01 弹窗的内联提示文本（其码位与状态不变）。

#### 4.1 责任与边界

- 技术依据：RC-M02-04、RC-M02-05、RC-M02-06、RC-M02-07、RC-M02-11（不落表的规则侧）、RC-M02-27（阶段字段）、RC-M02-30（服务端二次校验）；DEF-M02-05、DEF-M02-06、DEF-M02-07。
- 不承担的责任：不写库、不管事务（由 D-M02-02 编排）；不判定改名（D-M02-04）；不渲染表格（D-M02-05）；不定义阶段名称的字符集与长度上限（Q-M02-09 未规定，见 DQ-M02-09）；不决定去重比较是否忽略大小写（同上）。

#### 4.2 契约与结构

| 契约项标识 | 名称或操作 | 输入/结构 | 输出/约束 | 错误或边界 |
|---|---|---|---|---|
| D-M02-03/C-01 | `parse(String) → List<String>` | `project_info.stages` 原始文本（可能为 `null`、空串、JSON 数组文本、分隔符文本） | 文本以 `[` 起始时按 JSON 字符串数组解析；否则按 `[,;，；\n]` 拆分；逐项裁剪首尾空白并**忽略空白项**；**保序去重**（同名仅保留首个）；`null` 或空文本返回空集合 | 解析异常返回空集合并记录 `warn`，**不抛异常**（沿用既有容忍策略，避免读取路径因存量脏数据整体失败） |
| D-M02-03/C-02 | `normalize(List<String>) → List<String>` | 提交的阶段数组（可能含空白项、重复项） | 逐项裁剪首尾空白 → 忽略裁剪后为空的项 → **按输入顺序去重**（比较口径：区分大小写与全半角的精确字符串比较，口径待裁决见 DQ-M02-09）→ 返回有序集合 | 落实 RC-M02-06 三个分支；不改变输入顺序 |
| D-M02-03/C-03 | `validateLocked(List<String>) → void` | 规范化后的阶段集合 | DEF-M02-06 的四项锁定阶段必须全部存在；存在缺失时抛出 `M02-E003`（400），消息**列出全部缺失的锁定阶段**，顺序按 DEF-M02-06 固定顺序 | 落实 RC-M02-07；多个缺失时的文案拼接形态需求未规定，见 DQ-M02-20；本条**优先于**改名判定（D-M02-04/C-01 的前置条件） |
| D-M02-03/C-04 | `serialize(List<String>) → String` | 规范化后的阶段集合 | 以英文逗号 `,` 连接的文本（RC-M02-04） | 保存路径经锁定校验后集合至少 4 项，不存在空集合序列化分支；**不写入空串或 `null`** |
| D-M02-03/C-05 | `fallback(List<String>) → List<String>` | 解析后的集合 | 为空集合时返回 DEF-M02-07 的默认五阶段（需求分析、技术设计、代码生成、测试验证、知识沉淀），顺序固定；非空时原样返回 | 落实 RC-M02-05；仅用于读取路径，**不回写存储**（DD-M02-04）；不得报错 |
| D-M02-03/C-06 | 分隔符与容忍集合 | — | 写入恒用英文逗号；读取容忍 `,` `;` `，` `；` 与换行（技术选择，用于兼容存量非规范数据） | 阶段名称本身包含英文逗号时的处理需求未规定（Q-M02-09），本设计**不引入**转义或编码，该情形会被拆分，见 DQ-M02-09 |
| D-M02-03/C-07 | 常量来源 | — | 锁定阶段清单、默认阶段序列、分隔符均取自 D-M02-08 的单点声明 | 禁止在本构件内复制字面量，避免与 D-M02-01、D-M02-04 的取值漂移 |

- 本构件为**纯规则构件**：输入事实为「阶段文本或阶段数组」，输出为「规范化集合 / 校验结论 / 序列化文本 / 回落集合」，无副作用、无数据访问。唯一的副作用是解析异常时的 `warn` 日志。
- 规则在读取路径与保存路径**共用同一实现**：读取路径调用 C-01 + C-05，保存路径调用 C-02 + C-03 + C-04，保证「读到的」与「要保存的」按同一口径解释。

#### 4.3 处理逻辑

| 处理项标识 | 条件或触发 | 技术处理 | 状态/数据/外部效果 | 后续或结束 |
|---|---|---|---|---|
| D-M02-03/P-01 | `parse` 收到 `null` 或空白文本 | 直接返回空集合 | 无 | 结束 |
| D-M02-03/P-02 | `parse` 收到以 `[` 起始的文本 | 按 JSON 字符串数组解析成功则进入 P-04 | 无 | 解析失败 → 记录 `warn` → P-03 |
| D-M02-03/P-03 | 非 JSON 数组或解析失败 | 按 `[,;，；\n]` 拆分 | 无 | → P-04 |
| D-M02-03/P-04 | 已拆分或已解析 | 逐项裁剪首尾空白、丢弃空白项、保序去重 | 无 | 返回集合 |
| D-M02-03/P-05 | `normalize` 收到数组 | 逐项裁剪 → 丢弃空白项 → 保序去重 | 无 | 返回有序集合 |
| D-M02-03/P-06 | `validateLocked` 收到集合 | 计算「锁定阶段清单 − 集合」；差集非空 → 组装消息（逐项按固定顺序拼接）并抛 `M02-E003` | 无写入 | 差集为空 → 通过 |

#### 4.4 状态、数据与失败处理

- 读写数据：无数据读写（纯计算）；不修改传入集合。
- 事务边界：无。本构件不参与事务，其调用方（D-M02-02）保证校验与写入处于同一事务。
- 并发冲突：无共享状态；本构件无状态、可被并发安全调用。
- 重复请求：幂等（同一输入恒得同一输出）。
- 失败处理：唯一失败为锁定阶段校验失败（`M02-E003`），由调用方决定是否写入（保存路径为不写入并整体拒绝）；解析异常不向上抛，降级为空集合并由 C-05 回落为默认五阶段。
- 错误分类与传播：`M02-E003` 经 D-M02-09 出口；本构件不产生其他错误。
- 幂等与一致性：`normalize(parse(x))` 对同一文本稳定；`parse(serialize(s))` 在不含分隔符与大小写歧义时等于 `normalize(s)`（该等价性受 DQ-M02-09 的口径影响）。

#### 4.5 质量与可验证性

- 安全：不接触外部输入之外的资源；阶段名称不属敏感数据；不引入正则回溯风险（分隔符集合为单字符类）。
- 性能：与阶段项数线性相关；阶段数量受人工维护约束，量级可控。
- 日志与诊断：解析失败记录 `warn`（含原始文本的**长度**而非全文，避免脏数据刷日志）；校验失败不记录 `error`（属正常业务拒绝，由 D-M02-09 记 `warn`）。
- 可验证观察入口：`normalize` 的输出顺序即 RC-M02-06 分支b 的判定观察入口（AC-M02-07）；`validateLocked` 的消息即 RC-M02-07 的判定观察入口（AC-M02-08）；`fallback` 的输出即 RC-M02-05 的判定观察入口（AC-M02-06、AC-M02-40）；`serialize` 的输出即 RC-M02-04 的判定观察入口（AC-M02-05）。
- 受控验证：重复项、仅空白项、前后含空白项、输入顺序与字母序不同、缺 1 与缺多个锁定阶段、`stages` 为 NULL / 空串 / 仅含分隔符三类形态均可完全受控构造。
- 敏感信息：无。

- 已核对内容：输入（`text` 列原始值）、容忍的分隔符集合与 JSON 数组分支、空白项过滤、解析失败不抛异常的降级策略。

### D-M02-04 阶段改名判定与 Agent 归属迁移构件

#### 4.1 责任与边界

- 设计职责：以库中存储值为基准比较阶段集合差异，在「恰好删除 1 个且新增 1 个」时判定为阶段改名，并把该阶段下全部 Agent 的一级分类归属迁移为新阶段名。
- 调用者或使用方：D-M02-02（保存编排中的 P-09）。
- 依赖：D-M02-03（阶段解析与规范化，用于两侧集合的取得与比较）、D-M02-10（`agent_definition.category` 的批量写入）、D-M02-08（常量）。
- 技术依据：RC-M02-09、RC-M02-10（阶段来源侧）、RC-M02-11（不落分类表）、RC-M02-17（失败保持变更前状态）；DEF-M02-08、DEF-M02-15；DD-M02-04（比对基准）、DD-M02-05（不落表）、DD-M02-06（原子性）、DD-M02-09（不截断阶段名）。
- 不承担的责任：不写 `agent_category` 表（DD-M02-05）；不改写工作流阶段、节点与 Agent 绑定（RC-M02-10 的例外，Q-M02-10 见 DQ-M02-10）；不维护 Agent 定义本身（M10）；不判定锁定阶段的改名（该情形在 D-M02-02/P-08 已被拒绝，本构件不进入）；不处理「非 1 删 1 增」的多阶段增删（Q-M02-01 未规定，见 DQ-M02-01）。

#### 4.2 契约与结构

| 契约项标识 | 名称或操作 | 输入/结构 | 输出/约束 | 错误或边界 |
|---|---|---|---|---|
| D-M02-04/C-01 | 改名判定 | 基准集合（由**库中存储值**经 D-M02-03/C-01 解析得到）、目标集合（本次保存经 D-M02-03/C-02 规范化后的集合） | 计算 `删除集 D = 基准 − 目标`、`新增集 A = 目标 − 基准`；当 `|D| = 1` 且 `|A| = 1` 时判定为改名，`oldName = D 的唯一项`、`newName = A 的唯一项` | 落实 RC-M02-09；`|D| ≠ 1` 或 `|A| ≠ 1` 时判定为「非改名」，**不迁移**（含仅删除 1 个、仅新增若干、2 删 2 增等） |
| D-M02-04/C-02 | 非改名分支的可观察结果 | — | `agent_definition.category` **保持不变**（AC-M02-11） | 该分支不产生任何 Agent 侧写入；阶段删除与新增只影响 `project_info.stages` 与派生分类视图 |
| D-M02-04/C-03 | 迁移写入 | `oldName`（原阶段名）、`newName`（新阶段名） | 单条批量更新：`UPDATE agent_definition SET category = :newName, updated_at = :now WHERE category = :oldName`；返回受影响行数（仅用于日志，不参与判定） | 迁移范围即 DEF-M02-15 定义的「该阶段下全部 Agent」；**不写 `agent_category`**（RC-M02-11） |
| D-M02-04/C-04 | 迁移失败的原子性 | — | 写入异常向上抛出，由调用方所在事务回滚；阶段与 Agent 分类保持变更前状态 | 落实 RC-M02-17；不引入重试、补偿或回退，也不返回部分成功 |
| D-M02-04/C-05 | 执行顺序约束 | — | 本构件只在锁定阶段校验通过后被调用（D-M02-02/P-08 → P-09） | 落实 RC-M02-07 对 RC-M02-09 的优先关系：删除或改名锁定阶段不得触发迁移 |
| D-M02-04/C-06 | 迁入名的写入口径 | `newName` | 按阶段名**原值**写入，不截断、不做字符替换 | 目标列 `agent_definition.category` 为 `varchar(16)`，超长时由数据库拒绝并使保存失败；该选择使超长阶段名的 RC-M02-09 不可满足，见 DQ-M02-08 |
| D-M02-04/C-07 | 并发下的比对基准 | — | 基准取自同一事务内读取的当前存储值；并发保存的比对版本需求未规定（Q-M02-04） | 本设计不引入版本号或加锁，见 DQ-M02-04 |

- 判定输入的两个集合**必须来自不同来源**：基准来自数据库存储值（DD-M02-04），目标来自本次请求；不得用读取回落值作基准，否则「存储为空 + 回落五阶段 + 提交五阶段」会被判为 0 删 0 增（不触发迁移，结果相同），但「存储为空 + 提交非默认五阶段」会被误判为 1 删 1 增而触发错误迁移。
- 「该阶段下全部 Agent」按 `agent_definition.category` 精确等于 `oldName` 判定；不按名称前缀、不按模糊匹配（DEF-M02-15）。

|---|---|---|---|---|
| D-M02-04/P-01 | 保存请求携带 `stages` 且锁定校验通过 | 读取当前行的 `stages` 存储值，经 D-M02-03/C-01 解析为基准集合 | 只读 | → P-02 |
| D-M02-04/P-02 | 已取得两个集合 | 计算 `D`、`A`；判定 `|D| = 1 且 |A| = 1` | 无 | 成立 → P-03；不成立 → P-05 |

#### 4.4 状态、数据与失败处理

- 读写数据：读 `project_info.stages`（由 D-M02-02 在同一事务内已读取，避免二次查询拿到不同版本）；写 `agent_definition.category` 与 `updated_at`。**不读不写** `agent_category`、`workflow_stage`、`ai_conversation`。
- 事务边界：不自行开启事务，运行在 D-M02-02 的保存事务内；提交后可观察结果为「该阶段下全部 Agent 的 `category` 等于新阶段名」。
- 并发冲突：并发保存同一项目时，两次迁移可能基于同一基准并分别指向不同新名，后提交者覆盖先提交者（取决于行级锁的等待顺序）；**处理口径需求未规定**（Q-M02-04），本设计不引入乐观锁，见 DQ-M02-04。
- 重复请求：同一改名请求重复提交时，第二次的基准已是新阶段名，`D` 与 `A` 不同时满足 1 删 1 增（第一次已把集合改完），故不会再迁移，结果幂等。
- 失败处理：迁移失败即整体回滚（C-04）；**不默认增加重试或补偿**。
- 外部副作用与本地状态的一致性：本构件无外部系统副作用，唯一的写入在同一数据库事务内，与项目行的更新原子提交。
- 错误分类与传播：迁移失败不映射为专用错误码，按未预期异常返回 `M01-E006`（503）；这是刻意的选择——需求未要求为「迁移失败」给出专用提示形态，见 DQ-M02-15 打包项。
- 状态一致性观察：迁移完成后同一事务内写入项目行，故「阶段序列」与「Agent 归属」在提交点上一致，不存在半完成态（RC-M02-17）。

#### 4.5 质量与可验证性

- 安全：写入范围由 `category` 等值条件限定，不接受用户指定的表名或列名；不记录 Agent 的提示词等正文内容。
- 性能：单条批量 UPDATE，按 `category` 过滤；`agent_definition` 当前**无 `category` 索引**（数据模型第七章未列该索引），Agent 数量增长时该更新为全表扫描——索引建议见第 8 节，属外部 DDL 变更。
- 日志与诊断：迁移命中记录 `info`（含 `oldName`、`newName` 与受影响行数）；判定为非改名不记录；失败由 D-M02-09 记录 `traceId`。
- 可验证观察入口：`agent_definition.category` 的实测值是 RC-M02-09 与 AC-M02-10、AC-M02-11、AC-M02-39 的判定入口；`agent_category` 表的记录集合是 RC-M02-11 与 AC-M02-13 的判定入口（本构件对其无写入）。
- 受控验证：某非锁定阶段下挂若干 Agent 的数据可受控构造；迁移失败的构造须以真实写入异常触发（例如构造超长新阶段名使列宽拒绝，见 V-M02-41），**不以桩替代**事务回滚路径。
- 敏感信息：无。

#### 4.4 状态、数据与失败处理

- 读写数据：读取明细响应；写入仅通过 D-M02-02 的保存端点。页面本身不直接操作数据库、不缓存项目定义到 `localStorage`（项目定义区别于「当前项目标识」这一会话标识）。
- 事务边界：无（前端）；保存的事务边界在服务端。
- 并发冲突：同一用户重复点击保存由「提交中禁用主操作」缓解；跨用户并发保存的处理口径属服务端未决问题（DQ-M02-04）。页面不做乐观并发控制。
- 重复请求：保存请求为幂等语义（同值重复提交结果一致，`updated_at` 刷新）；不做请求去重之外的额外机制。
- 部分失败：不提供部分保存。任何字段校验失败即整次保存被拒绝，页面保留用户输入。
- 超时与中断：请求超时（前端 `http.js` 的 10s）按保存失败处理（P-10），提示「请求超时，请稍后重试」；不自动重试。
- 资源占用与释放：视图卸载时清理事件监听与容器内容（沿用 `mountPlaceholder` 的 `destroy` 约定）。
- 错误分类与传播：按错误码分支处理——`M02-E001` / `M02-E002` / `M02-E003` / `M01-E002` / `M01-E003` / `M01-E006` 一律以浮动提示展示 `message`，不做页面级跳转（与 M01 项目弹窗的导航级处理不同，因为 M02 页面不承担项目上下文切换）。
- 敏感信息：不将任何字段写入 URL；不使用 `innerHTML` 渲染用户输入（沿用既有 `textContent` 约定，避免注入）。

#### 4.5 质量与可验证性

- 安全：用户输入一律以 `textContent` 写入 DOM；名称 `maxlength=128` 与服务端校验双重约束；页面不展示账号、密钥等字段。
- 性能：单次页面加载 1 次读取请求；保存 1 次写请求；阶段表格为纯本地渲染，阶段数量受人工维护约束。
- 日志与诊断：前端不产生业务日志；失败时以浮动提示呈现响应体 `message`（含 `traceId` 时不展示给用户，避免暴露内部细节——`ApiError` 携带 `traceId` 供服务端日志关联）。
- 可验证观察入口：页面标题、说明、主操作、提示条、输入框 `maxlength`、阶段表格结构构成 RC-M02-29、RC-M02-30 的静态契约观察入口（AC-M02-35、AC-M02-36）；锁定行的元素构成是 RC-M02-08 的观察入口（AC-M02-09）；提示形态是 RC-M02-31 的观察入口（AC-M02-37）；失败态是 RC-M02-25 的观察入口（AC-M02-31）；保存后顶栏是 RC-M02-22 的观察入口（AC-M02-25）。
- 受控验证：读取失败以真实异常出口构造（停表或数据源不可用），不以桩替代后端异常路径；提示文案依据 DEF-M02-14 与 Q-M02-15 的结论核对。
- 阶段表「序号徽标超过两位」与「阶段数量上限」无需求依据，不构造该边界作为验收断言（DQ-M02-13）。

## 5. 跨单元协作设计

### 5.1 协作机制与边界（D-M02-12）

本模块的协作全部发生在**同步的人机交互路径**上：由一次用户动作（打开页面、保存配置）触发，经前端表单装配、一次接口调用、服务端事务内的一次或多次写入完成，无异步受理、无批量提交、无调度、无跨系统一致性机制。阶段改名的 Agent 归属迁移虽然是一次批量更新，但它在保存事务内同步完成，不属于异步协作。因此本节不定义「受理 / 处理中 / 完成」状态机，也不定义补偿与恢复流程；需要明确的只有四件事：**触发顺序、事务边界、失败传播范围、剩余活动处理**。

本模块唯一的并发风险有两处：①并发保存同一项目时后提交者覆盖（无版本字段，数据模型第八章第 1 项）；②并发读取在平台无项目时可能创建多条默认项目行（`project_info` 无唯一业务键）。两者的处理口径需求均未规定（Q-M02-04、Q-M02-07），本设计**不引入锁、版本号或唯一约束**，统一登记为 DQ-M02-04、DQ-M02-07，不在协作机制中自行决定失败政策。

### 5.2 跨单元条款的整体成立条件

- **AC-M02-39（RC-M02-09、RC-M02-10、RC-M02-11 联合）**：需 D-M02-12/P-02 在**同一会话内连续成立**——Agent 归属迁移至新阶段名、分类列表与阶段序列同名同步、`agent_category` 记录集合未变化。三项的观察入口分属三个系统（`agent_definition` 表、M10 的分类列表、`agent_category` 表），仅验证其中一项（如只看 `project_info.stages` 已更新）不足以判定满足。其中分类列表部分依赖 M10（DQ-M02-19）。
- **AC-M02-40（RC-M02-05、RC-M02-06、RC-M02-07 联合）**：需 D-M02-01/P-05 的回落与 D-M02-02/P-08 的锁定校验同时成立——回落值含全部四项锁定阶段，故「不修改阶段直接保存」不会被锁定校验误拒；同时 D-M02-12/P-01 的比对基准取**存储值**（空），保存被判为「新增 5 项」，不触发迁移。基准若改为回落值，该联合要求仍成立（0 删 0 增），但 AC-M02-10 的判定基准会随之变化（DQ-M02-04）。
- **AC-M02-03（RC-M02-01 与 RC-M02-02 联合）**：需 D-M02-02/C-04 的规范化与长度判定顺序固定为「先裁剪、后判长」；两者顺序颠倒会产生「含前后空白导致超限误报」的结果。
- **AC-M02-08 与 AC-M02-09（RC-M02-07 与 RC-M02-08 联合）**：服务端拒绝（D-M02-03/C-03）与前端只读（D-M02-05/C-06）必须同时成立；仅前端只读不能防止构造请求绕过，仅服务端校验不能防止界面提供改名入口。两者的共同成立条件是**同一份锁定阶段清单**——前端取服务端下发的 `lockedStages`（D-M02-01/C-06），服务端取 D-M02-08/C-01 的常量，两者同源。
- **跨接口口径一致（阶段解析）**：项目信息读取（D-M02-01）与全局上下文读取（M01 `D-M01-01`）分属两次请求，若各自实现阶段解析即存在口径漂移，故该规则被抽取为 D-M02-03 的单点实现（D-M02-12/P-07）；共同成立条件是该构件为唯一解析入口，任何一处绕过即视为不满足。
- **跨模块边界**：RC-M02-10 的消费侧（Agent 分类列表）、RC-M02-14…RC-M02-16、RC-M02-22 会话侧与 RC-M02-23（AI 会话上下文）分别作用于 M10 与 M27；M02 只提供阶段来源与注入字段读取契约，这些条款的**整体成立**取决于下游模块按其口径消费（第 6 节标注为待补充，第 7 节标注验证层级为跨模块）。
