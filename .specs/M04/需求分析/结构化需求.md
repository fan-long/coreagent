# M04 应用类型 —— 模块需求（OpenSpec 风格 · 能力基线 Spec）

> 用途：以 OpenSpec Spec 结构描述一个模块当前已具备的能力基线，作为技术设计、代码生成与测试验证的输入。
> 文档类型：Spec（现状基线）；跨模块的增量变更由「功能点（ft）」以 Change 方式另行表达，不写入本文档。
> 编写单位：一个模块一份文档；能力（Capability）是需求的最小可验收单元。
> 通用性说明：本模板为通用模板，不预设任何项目的功能域、分组枚举与模块划分；模块编号、模块名称、所属分组、应用组件标识均取自使用方的模块字典。

## 1. 背景与目标

### 1.1 现状与问题

应用类型是一个「类型（维度）— 类型值—值说明」两层的平面字典，用于多维度刻画应用组件的特征，并作为 Spec 组适用范围的勾选对象。平台已内置 9 个维度、37 个类型值（行业领域、用户对象、业务处理性质、数据处理模式、技术架构风格、实时性要求、质量属性侧重点、系统生命周期等）。现状实现为单表平铺存储：类型不是独立实体，新增时若填写了新的类型名称即自动形成新类型；删除以「单条取值」或「整个类型级联」两种粒度提供；类型值被 Spec 组关联后删除该类型值不会联动清理关联记录。

### 1.2 目标与成功标准

- 目标：以最少的维护成本维护应用组件特征维度，并让 Spec 组能够按类型值精确圈定适用范围。
- 成功标准：同一类型下不出现重复类型值；新增类型无需单独建维度记录；删除类型后其取值不再出现在列表中。

### 1.3 非目标（明确不做）

- 不维护应用组件实例与类型值的绑定关系：见 M03 应用组件。
- 不维护 Spec 组与阶段模板：见 M06 Spec模板与任务类型。
- 不定义类型值的级联校验与引用完整性约束。

### 1.4 关键约束

- 类型与类型值均必填，保存时裁剪前后空白；值说明可留空。
- 同一类型下类型值唯一（新增与更新均校验，更新时排除自身）。
- 类型与类型值均为文本，长度上限分别为 64 字符，值说明上限 255 字符。
- 删除类型值不校验 Spec 组关联，关联记录由 Spec 模板页的「全量替换」方式维护。

## 2. 领域术语表

| 术语 | 定义 | 来源/约束 |
|---|---|---|
| 应用类型 | 刻画应用组件特征的维度，如「行业领域」「用户对象」 | 类型名唯一标识该维度，非独立实体 |
| 类型值 | 某一维度下的可选取值，如「金融」「微服务」 | 同一类型下唯一 |
| 值说明 | 类型值的含义解释，用于下拉与勾选时的可读性 | 可空文本 |
| Spec 组关联 | Spec 组勾选适用的应用类型值集合 | 见 M06，按全量替换维护 |
| 预置维度 | 平台内置的类型与类型值 | 可被编辑或删除，不属于锁定数据 |

## 3. 业务场景

- 场景描述：平台维护人员在项目初期确认应用组件需要从哪些维度描述，按需裁剪或扩充维度与取值；随后在 Spec 模板页按这些取值圈定各 Spec 组的适用范围。
- 触发条件：新增或调整组件分类口径、Spec 组需要新的适用范围取值、清理无用的类型值。
- 参与角色：项目架构师（维护）、业务分析人员（查看）。
- 主流程：进入「环境管理 / 模板管理 / 应用类型」→ 左侧选择或新增类型 → 右侧维护类型值与值说明 → 保存。
- 分支流程：删除单条取值；删除整个类型（连同其全部取值）；取消新增。

## 4. 业务规则与不变量

| 规则编号 | 规则内容 | 适用范围 | 违反应如何处理 |
|---|---|---|---|
| BR-M04-01 | 类型必填，保存时裁剪前后空白，长度上限 64 字符 | 新增、编辑 | 拒绝保存并提示「请填写类型」 |
| BR-M04-02 | 类型值必填，保存时裁剪前后空白，长度上限 64 字符 | 新增、编辑 | 拒绝保存并提示「请填写类型值」 |
| BR-M04-03 | 值说明可留空，保存时裁剪前后空白，空值按空字符串存储，长度上限 255 字符 | 新增、编辑 | 不触发校验 |
| BR-M04-04 | 同一类型下类型值不可重复；更新时排除自身记录后校验 | 新增、编辑 | 拒绝保存并提示「类型「X」下已存在类型值「Y」」 |
| BR-M04-05 | 新增类型值时若填写的类型名称不存在，则自动形成新类型，无需单独创建维度记录 | 新增 | 自动形成新类型，不报错 |
| BR-M04-06 | 列表按排序号升序、同排序号按 ID 升序返回；预置维度按预设分类顺序展示 | 列表 | 顺序自动生效 |
| BR-M04-07 | 删除单条类型值只删除该取值记录，不影响同类型下其它取值 | 删除 | 删除成功并刷新列表 |
| BR-M04-08 | 删除整个类型时，该类型下全部类型值记录一并删除 | 删除类型 | 删除成功并提示「类型「X」及其 N 条取值已删除」 |
| BR-M04-09 | 删除类型不存在的类型或记录时拒绝操作 | 删除、删除类型 | 提示「应用类型记录不存在：X」或「类型不存在：X」 |
| BR-M04-10 | 应用类型值被 Spec 组关联后，删除该类型值不联动清理关联记录；关联由 Spec 模板页按勾选结果全量替换 | 删除、Spec 组关联 | 不做级联清理，无提示 |
| BR-M04-11 | 类型列表按类型聚合展示取值数量，供维护人员快速判断维度规模 | 列表 | 数量按当前取值行实时统计 |

## 5. 能力规格（Capabilities & Expectations）

### CAP-M04-01 应用类型列表查看

- 目的：以「类型—类型值」主从视图呈现字典结构。
- 范围边界：只读展示；左侧为类型维度列表，右侧为所选类型的取值表。
- 关联规则：BR-M04-06、BR-M04-11
- 验收预期：
  - GIVEN 字典中存在多个类型 WHEN 打开应用类型页 THEN 左侧按类型聚合展示，每个类型显示名称与其取值数量，右侧默认展示首个类型的取值表
  - GIVEN 某类型下存在取值 WHEN 查看右侧表格 THEN 展示类型值、值说明与操作列
  - GIVEN 字典中不存在任何类型 WHEN 打开应用类型页 THEN 右侧展示空态「暂无应用类型，点击右上角「新增」添加」
  - GIVEN 某类型下无取值 WHEN 查看右侧表格 THEN 展示空态「该类型下暂无取值，点击右上角「新增」添加」
  - 异常预期：GIVEN 字典接口不可用 WHEN 打开页面 THEN 展示失败提示而非空态文案

### CAP-M04-02 新增类型值

- 目的：在不新增独立维度记录的前提下扩充字典。
- 范围边界：产生一条类型值记录；类型名称可由用户改写从而形成新类型。
- 关联规则：BR-M04-01、BR-M04-02、BR-M04-03、BR-M04-04、BR-M04-05
- 验收预期：
  - GIVEN 填写类型与类型值 WHEN 保存成功 THEN 新取值出现在对应类型的取值表中，类型列表的取值数量同步更新
  - GIVEN 填写的类型名称在字典中不存在 WHEN 保存成功 THEN 自动形成新类型并出现在左侧类型列表
  - GIVEN 未填写类型或类型值 WHEN 保存 THEN 拒绝保存并提示「请填写类型」或「请填写类型值」
  - GIVEN 填写的类型值在该类型下已存在 WHEN 保存 THEN 拒绝保存并提示「类型「X」下已存在类型值「Y」」
  - 异常预期：GIVEN 保存失败 WHEN 提交 THEN 新增行保留并提示失败原因，不写入本地字典

### CAP-M04-03 编辑类型值

- 目的：修正类型、类型值或值说明。
- 范围边界：可修改类型名、类型值与值说明；不改变记录标识。
- 关联规则：BR-M04-01、BR-M04-02、BR-M04-03、BR-M04-04
- 验收预期：
  - GIVEN 修改某条取值的类型值或值说明 WHEN 保存成功 THEN 表格展示最新内容，并按新类型重新归组
  - GIVEN 修改后与同类型下其它取值重复 WHEN 保存 THEN 拒绝保存并提示重复
  - GIVEN 记录不存在 WHEN 保存 THEN 提示「应用类型记录不存在：X」
  - 异常预期：GIVEN 保存失败 WHEN 提交 THEN 表格回显修改前内容并提示失败原因

### CAP-M04-04 删除类型值

- 目的：清理不再使用的取值。
- 范围边界：仅删除该条取值记录；不做引用校验与级联清理。
- 关联规则：BR-M04-07、BR-M04-09、BR-M04-10
- 验收预期：
  - GIVEN 某类型下存在多条取值 WHEN 删除其中一条 THEN 该条被移除，其余取值保留，类型列表计数同步更新
  - GIVEN 该取值已被 Spec 组关联 WHEN 删除 THEN 取值得以删除且不提示，Spec 组关联记录保持原状
  - 异常预期：GIVEN 记录不存在 WHEN 删除 THEN 提示「应用类型记录不存在：X」

### CAP-M04-05 删除整个类型

- 目的：一次性清理某个特征维度。
- 范围边界：删除该类型下全部取值行；类型本身无独立记录，删除后即消失。
- 关联规则：BR-M04-08、BR-M04-09
- 验收预期：
  - GIVEN 某类型下存在 N 条取值 WHEN 确认删除该类型 THEN 该类型及全部取值被删除，提示「类型「X」及其 N 条取值已删除」，左侧列表不再展示该类型
  - GIVEN 未指定类型名称 WHEN 请求删除 WHEN 拒绝并提示「请指定类型」
  - 异常预期：GIVEN 类型不存在 WHEN 请求删除 THEN 提示「类型不存在：X」

### CAP-M04-06 类型值供 Spec 组关联

- 目的：让 Spec 组能按应用类型值圈定适用范围。
- 范围边界：只提供可选值集合；关联关系的维护在 Spec 模板页完成。
- 关联规则：BR-M04-10
- 验收预期：
  - GIVEN 字典中存在类型值 WHEN 在 Spec 模板页打开关联编辑 THEN 按类型分组展示全部类型值供勾选
  - GIVEN 某 Spec 组已勾选部分类型值 WHEN 查看该组 THEN 以徽标形式展示已关联的类型值，未关联时展示「未关联应用类型值」
  - 异常预期：GIVEN 字典为空 WHEN 打开关联编辑 THEN 展示「暂无可选的应用类型值，请先在「应用类型」页维护」

## 6. 界面规格

### UI-M04-01 应用类型页

- 位置与入口：环境管理 / 模板管理 / 应用类型
- 页面标题与说明：标题「应用类型」；说明「维护应用组件的类型分类：左侧选择类型，右侧维护该类型下的类型值与值说明，用于多维度刻画应用组件的特征」
- 主操作：右上角「新增」
- 元素清单：左侧类型列表（类型名、取值数、选中态；页脚统计「N个类型 · M条取值」）；右侧取值表（类型值、值说明、操作）
- 交互规则：点击左侧类型切换右侧内容；点击右侧行内输入框直接编辑
- 状态与反馈：无类型时展示空态；某类型无取值时展示空态

### UI-M04-02 类型值表格行

- 元素清单：类型值输入框（占位「类型值，如 金融」）、值说明输入框（占位「取值含义，可留空」）、保存与删除按钮
- 交互规则：行内编辑后点击保存提交；新增行提供取消按钮
- 状态与反馈：保存失败以浮动提示给出原因，行内容保留

### UI-M04-03 新增类型值页

- 位置与入口：应用类型页右上角「新增」
- 页面标题与说明：标题「新增」；说明「在当前所选类型下追加类型值；如需新增类型，修改类型名称即可」
- 主操作：「保存」；次要操作「取消」
- 元素清单：类型名称（默认回填当前所选类型）、类型值、值说明
- 交互规则：修改类型名称即形成新类型；取消则关闭且不写入
- 状态与反馈：保存成功后关闭并刷新主从视图

### UI-M04-04 删除类型

- 位置与入口：右侧详情标题行「删除类型」
- 元素清单：删除按钮（危险样式）
- 交互规则：删除前提示将连同该类型下全部取值一并删除
- 状态与反馈：删除成功提示「类型「X」及其 N 条取值已删除」

## 7. 业务对象与属性

| 对象 | 关键属性 | 业务含义 | 必填 | 取值与约束 |
|---|---|---|---|---|
| 应用类型值 | 记录ID | 取值记录唯一标识 | 是 | 自增主键 |
| 应用类型值 | 类型 | 所属特征维度名称 | 是 | 最长 64 字符，裁剪空白；同名即同一维度 |
| 应用类型值 | 类型值 | 维度下的取值 | 是 | 最长 64 字符，裁剪空白；同类型下唯一 |
| 应用类型值 | 值说明 | 取值含义解释 | 否 | 最长 255 字符，空值按空串存储 |
| 应用类型值 | 排序号 | 同类型内的展示顺序 | 否 | 整数，升序展示；预置维度按预设顺序 |
| Spec 组关联 | 组ID + 类型值 | Spec 组适用的类型值 | 是 | 组合唯一；按全量替换维护，不随类型值删除而清理 |

派生展示信息（不单独存储）：类型列表的取值数量、类型总数、取值总数。

## 9. 异常、边界与失败模式

| 场景 | 处理要求 | 关联能力/规则 |
|---|---|---|
| 类型或类型值为空 | 拒绝保存并提示具体字段 | CAP-M04-02、CAP-M04-03、BR-M04-01、BR-M04-02 |
| 同类型下类型值重复 | 拒绝保存并提示重复 | CAP-M04-02、CAP-M04-03、BR-M04-04 |
| 记录或类型不存在 | 提示「应用类型记录不存在：X」/「类型不存在：X」 | CAP-M04-03、CAP-M04-04、CAP-M04-05、BR-M04-09 |
| 删除被 Spec 组关联的类型值 | 照常删除，不联动清理关联记录 | CAP-M04-04、BR-M04-10 |
| 字典为空时打开 Spec 组关联编辑 | 展示引导文案，不展示空勾选面板 | CAP-M04-06 |
