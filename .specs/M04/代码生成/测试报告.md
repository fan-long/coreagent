## 4. 设计一致性核对（实现与详细设计的偏差）

| 项 | 设计约定 | 实现 | 判定 |
|---|---|---|---|
| D-M04-06/C-02 裁剪口径 | 字面写 `trim()` | `String.strip()`（`AppTypeRules.normalize`） | **偏差（已登记）**：同单元 C-06 与 RC-M04-01、TC-01 要求覆盖全角空格（U+3000），`trim()` 无法满足；`strip()` 在 ASCII 空白域是 `trim()` 的严格超集，行为一致 |
| D-M04-02/P-06、D-M04-03/P-06 写入 | 字面写 `save` | `saveAndFlush` | **偏差（已登记）**：`save` 的 flush 发生在服务层 `try` 块之外的事务提交阶段，库级唯一键冲突会逸出为 `M01-E006`（503）而非设计要求的 `M04-E006`（409）；改用 `saveAndFlush` 后异常在 `try` 块内暴露，契约测试实测 `409 + M04-E006` 成立 |
| D-M04-11/C-02 有序读取 | `ORDER BY sort_order ASC, id ASC` | JPQL `ORDER BY c.sortOrder ASC, c.id ASC` | 一致（属性路径，规避 JPQL 裸 `value` 标识符冲突，C-11） |
| D-M04-11/C-10 批量删除 | `@Modifying @Query` 返回受影响行数 | `int deleteByType(@Param("type") String type)` | 一致；`deletedCount` 取实际受影响行数（D-M04-05/P-03 的取舍），TC-19/TC-44 实测与删除前计数相等 |
| D-M04-12/C-01 视图分派 | 在 `case 'env'` 内增加 `pageKey` 判定 | 抽出 `mountEnvPage(route)` 以 `switch (pageKey)` 分派 | **等价重构**：判定结果与设计一致（`project` → 项目信息页、`app-type` → 应用类型页、其余 → 占位页），可读性优于嵌套三元；不影响既有页面 |
| D-M04-12/C-02 请求扩展 | 追加 `del` | `http.js` 导出对象新增 `del: (path) => request(path, { method: 'DELETE' })` | 一致（追加式，不改 `request` 既有行为） |
| D-M04-14/C-02 预置维度 | 仅声明已知 8 项，不编造 | `AppTypeCatalog.PRESET_TYPE_NAMES` 恰为 8 项且不参与运行时排序 | 一致 |
| D-M04-10/C-06 错误文案 | 枚举文案列为 `类型「X」下已存在类型值「Y」` | 枚举兜底文案为「类型下已存在该类型值」，抛出点一律用 `BizException(ErrorCode, String)` 组装动态文案 | **偏差（已登记）**：对外可观察文案与设计逐字一致（TC-11/TC-13/TC-43 实测），仅枚举无参兜底文案不同 |
| D-M04-10/C-07、C-08 | 枚举文案列含 `X` 占位 | 兜底文案为不含占位符的固定串，抛出点组装动态文案 | 同上，对外行为一致 |

**未发现**实现与设计在业务判定、错误码、HTTP 状态、文案（对外可观察部分）、事务边界、排序口径上的实质偏差。
