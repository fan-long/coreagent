# M07 模型配置 —— 结构化需求规格

> 本规格依据《通用结构化需求》模板编制，将 M07 模块的 OpenSpec 能力基线（原始需求）与数据模型设计转换为统一、可追踪、可验证的需求规格。
>
> 需求条款（RC）是统一追踪单元；共享定义（DEF）提供语义；能力（CAP）组织条款；验收检查点（AC）定义验证义务。
>
> 本规格不替代技术设计、实施任务或测试报告，也不因填写完成而证明实现正确。
>
> 条款编号采用统一追踪编号 RC-M07-01…RC-M07-26；「来源」列同时标注源文档的原始编号（BR-M07-xx / CAP-M07-0x / UI-M07-0x），以便与源文档互查。能力编号沿用源文档 CAP-M07-01…CAP-M07-05，检查点编号 AC-M07-01…AC-M07-36，待决事项编号 Q-M07-01…Q-M07-16。
>
> 测试案例说明：本阶段输入为「任务类型 mod 任务项 M07 下无未禁用（启用）测试案例」，即 M07 无既有可用测试案例，故本阶段测试案例清单全部为新增案例（无复用、修改与删除项）。

### 1.2 目标与边界

- **业务目标**：让平台可用的模型标识、名称、双协议端点与两套凭据可被集中、唯一地维护，作为 Agent 配置与通用 Agent 集成的唯一模型来源；同时保证未修改凭据时保存不会误覆盖既有明文。
- **成功标准**：新增模型后立即可在 Agent 配置与通用 Agent 集成的模型下拉中被选择；未修改 ApiKey 时保存不会覆盖原值（SRC-001 §1.2）。
- **建设对象**：core-agent 平台 M07 模块范围内的模型配置页（环境管理 / 系统配置 / 模型配置）、左侧模型列表与右侧模型表单，以及模型配置的新增、列表读取、编辑与删除处理。
- **纳入范围**：
  - 模型配置的新增、列表读取、详情查看、编辑与删除；
  - 模型 ID 的必填、空白裁剪、长度上限、全局唯一与创建后不可修改；
  - 展示序号的递增生成与列表升序返回；
  - 前端 / 后端 ApiKey 的掩码返回与掩码提交判定；
  - 模型目录对下游（Agent 配置、通用 Agent 集成）的取值供给。
- **排除范围**：
  - 不维护 Agent 定义与提示词模板（对应 M10 Agent 配置，SRC-001 §1.3）；
  - 不维护通用 Agent 工具的 CLI 路径与环境变量（对应 M08 通用Agent集成，SRC-001 §1.3）；
  - 不实现调用计量、配额与成本统计（SRC-001 §1.3）；
  - 不提供 ApiKey 的加密存储与轮换策略（SRC-001 §1.3，现状为明文入库 + 掩码展示）；
  - 不定义模型级权限、审计留痕与多租户隔离策略（平台尚未具备该能力，SRC-002 §1.2、§9）；
  - 跨模块的增量变更以功能点（ft）方式另行登记，不在本规格范围。
- **外部责任**：
  - Agent 配置的模型下拉与 Agent 默认模型的落库由 M10 Agent 配置承担，M07 只提供取值集合（SRC-001 §8）；
  - 通用 Agent 集成的默认模型下拉与按模型维度的环境变量由 M08 通用Agent集成承担，M07 只提供取值集合（SRC-001 §8）；
  - 任务执行时对模型的消费由 M23 任务管理与流程执行承担（SRC-001 §8）；
  - 模型调用与 Token 统计的留痕由 ai_message / workflow_run 承担（SRC-002 §4.2、§4.4），M07 不承载调用计量。

## 3. 可验证需求条款

### 3.1 条款定义

需求条款是在明确的适用范围和条件下，对目标系统提出的一项可独立判断是否满足的要求。一条条款可以包含同一决策的多个分支，分支以「分支a / 分支b / 分支c」标注并可分别验证。能够分别违反、分别修改的要求已尽可能拆分。

### 3.2 条款类型

| 类型 | 表达内容 | 重点检查 |
|---|---|---|
| 业务规则 | 许可、禁止、决策、计算及业务不变量 | 条件、结论、计算口径、例外及优先级 |
| 功能行为 | 必须执行的动作、状态变化和业务效果 | 触发、动作、完成条件、成功及失败结果 |
| 数据要求 | 数据结构、含义、关系、记录与保留要求 | 对象范围、数据契约、关联及有效性 |
| 交互契约 | 人机或系统间的信息交换与协作 | 输入、输出、错误、关联标识及交互时序 |
| 质量约束 | 规定条件下的质量指标与保障要求 | 环境、负载、指标、阈值及测量口径 |

每条条款选择一个主类型登记。本规格不登记质量约束类条款：来源未给出可测量的质量指标（环境、负载、统计窗口、阈值），§1.2 的两项成功标准均为可判定的功能结果，已分别由 RC-M07-25、RC-M07-08 承载，不编造阈值。

### 6.2 验证形式说明

- **场景验证**：给定具体条件、操作或事件，检查预期结果，适合正常、异常、边界和状态分支。本规格多数检查点采用此形式。
- **性质验证**：在明确输入域、状态域或操作序列中检查应持续成立的关系。本规格未单独采用：来源未给出可枚举的输入域或操作序列不变量（RC-M07-11 的序号唯一递增已通过 AC-M07-16、AC-M07-36 以具体场景验证，避免引入原需求未规定的不变量）。
- **测量验证**：在规定环境、负载和时间窗口中测量指标。本规格未采用：来源未给出可测量的质量指标（见 3.2）。
- **静态契约检查**：检查结构、声明、接口或其他可静态判定的约束。本规格用于对象结构（AC-M07-18、AC-M07-33）、预置清单（AC-M07-17）、不可修改字段（AC-M07-05）与页面结构（AC-M07-11、AC-M07-21、AC-M07-22）。

未为使用性质测试而增加原需求没有规定的不变量、幂等或可逆性要求。
